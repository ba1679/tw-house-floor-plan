# 幾何契約

## 為什麼你不能直接寫座標

LLM 很會決定「廚房應該挨著餐廳」，很不會做**必須剛好閉合的算術**。
矩形填滿 bounds 且不重疊、不留縫，是一組要同時成立的等式；靠事後 nudge 修不回來
（推開重疊 → 產生空隙 → 推回去 → 換一組重疊，無限迴圈）。

所以這個 skill 的分工是：

```
你負責                        程式負責
─────────────────────────    ─────────────────────────
拓樸（誰挨著誰）              房間座標
比例（誰佔多少）              牆的位置與型別
語意（門通到哪、窗開哪面）     開口的 wall_id 與 offset
```

**你寫 layout（格局），不寫 floorplan（平面圖）。** floorplan 由 `expand_layout.py` 產生。

## 平面圖是什麼：離地 120~150cm 平切下視

上一節講的是「誰算座標」，這一節講「為什麼平面圖長這樣」。
《室內設計裝修製圖規範》p44 §15.2：

> 平面圖為約在地面上 **120~150cm 平切下視**，作正投影，所得之剖面圖……
> 此一剖面不論其距地板高度為若干，**均須切過該層所有門窗開口**。

一句話記住結論：

> **實線＝切到的、或從上面看得到的；虛線＝頭頂上的。**

下面每一條畫法都是從這一句推出來的，不是各自獨立的美術決定：

| 畫法 | 為什麼 | 出處 | 現況 |
|---|---|---|---|
| 高櫃（衣櫃、冰箱）矩形內畫 **X** | 比切面高，**被切到了** | p25 表 10 備考 | 已實作 |
| 半高櫃畫**一條斜線** | 剛好在切面附近 | p25 表 10 備考 | 未實作（型錄目前沒有這一類） |
| 矮櫃（廚房檯面）**不加記號** | 在切面**以下**，是看到的 | p25 表 10 備考 | 已實作 |
| 吊櫃、壁掛電視畫**虛線** | 在切面**以上**，是投影下來的 | p25 表 10 備考 | 已實作 |
| 樑畫**長虛線** | 同理，樑在頭頂上 | p18 表 6 | **不做**，見下 |

因此 `rules/furniture.md` 的 `TALL` / `WALL_MOUNTED` 分類有兩個用途，不要只當成碰撞規則：
它同時決定該件家具在圖上**畫成 X 還是虛線**。

還有兩個推論值得記住：

- **開口一定被切到。** 規範說剖面「均須切過該層所有門窗開口」——所以牆在門窗處一定斷開，
  這不是畫法選擇。renderer 的做法（先畫牆、再用開口把牆挖空、最後補門樘窗樘）就是這句話的結果。
- **這是天花板圖的分界線。** 燈具、撒水頭、偵煙器、空調、開關插座屬於**另外幾張圖**
  （p9 表 3 把平面配置圖、天花板圖、開關插座圖、給排水圖列為不同的圖說），
  不該畫進平面配置圖。要支援天花板圖時，界線就在這條切面的上方。

> **樑刻意不畫（決議）。** 規範確實把梁線列為平面圖的長虛線，但**買房者實際看到的建案平面圖不畫樑**——
> 樑屬於施工圖與結構圖。本 skill 的目標是產出「像使用者在外面看到的那種圖」，所以不畫。
>
> 代價要知道：樑是「頭頂上的東西」最典型的例子，少了它，上面這一課在生成的圖上
> 只有高櫃與壁掛物兩個例子，講得完但不夠有力。等之後的 phase 要做施工圖或剖面圖時再回來看。

## 座標系

```
unit: cm    origin: 左上    x →    y ↓
```

所有數值四捨五入到整數公分。切割時是對「切線位置」取整，不是對「寬度」取整——
相鄰房間因此共用同一個整數邊界，不會出現 1cm 的縫。

## Slicing tree

`tree` 是一棵遞迴切割樹。每個節點不是葉子（一個房間）就是一刀切割。

```jsonc
{ "stack": "rows",              // rows = 子節點由上往下；cols = 由左往右
  "ratios": [0.55, 0.45],       // 會自動正規化，不必剛好加起來等於 1
  "children": [ ... ] }         // 長度必須等於 ratios
```

葉子：

```jsonc
{ "id": "room-living", "room": "living_room", "name": "客廳" }
```

**這個結構天生保證**：房間鋪滿 bounds、零重疊、零空隙、無負尺寸。
Constraint 1 / 2 / 6 不是「驗證通過」，是**表達不出違規狀態**。

代價：只能做矩形分割。要 L 形空間，就切成兩個相鄰的矩形房間
（例如 `living_room` + `dining_room`），不要試圖描述凹多邊形。

## 牆是推導出來的

不要寫牆。每一條切割線就是一面 `interior` 牆，外框四邊是 `exterior` 牆
（列在 `party_walls` 的那幾邊變成 `party`，代表與鄰戶相接，不得開窗）。

牆的方向永遠正規化：**水平牆 start→end 由左至右，垂直牆由上至下**。
`offset` 一律從 `start` 起算。

兩側房間：**水平牆 `rooms_a` 在上、`rooms_b` 在下；垂直牆 `rooms_a` 在左、`rooms_b` 在右。**

預設厚度：外牆 24cm、內牆 12cm（RC 大樓常見值），可用 `wall_thickness` 覆寫。
房間的 `geometry` 是到牆**中心線**，`inner` 才是扣掉半個牆厚後的淨空間——
傢俱與熱區都以 `inner` 為界。

## 開口用語意描述，不用座標

```jsonc
// 室內門：兩間房之間
{ "id": "door-master", "between": ["room-hall", "room-master"], "width": 90 }

// 對外門／窗：某間房的某一面外牆
{ "id": "win-living", "room": "room-living", "side": "n", "width": 200 }
```

展開器會找出共用牆段，把 `at`（0..1，預設 0.5）換算成 `wall_id + offset`，
再推出世界座標 `position`。因此：

- **門必然長在牆上**（Constraint 3 無法違反）
- **窗必然開在外牆上**（Constraint 4 無法違反）

解析不到就是硬錯誤，展開器會直接失敗並告訴你原因，例如
「room-hall 與 room-master 沒有共用牆段」或「共用段只有 98cm，裝不下 100cm 的門」。
**這種訊息是要你改 spec，不是改程式。**

## 淨空模型：門窗周圍的禁區

房間座標由切割樹保證合法，但「門打得開嗎、走得過去嗎」還需要另一層。
展開器會替每個開口算出禁區，**在擺放傢俱時就當成障礙物**，不是事後檢查：

```
     ┌─────────────────┐
     │                 │
     │   ╱ 開啟弧線     │   四分之一圓，半徑 = 門寬
     │  ╱  R = 門寬     │   落在門開向的那一側
   ══╪═╱═══════════════│
     │ ← 60cm →        │   通行空間：門寬 × 60cm，兩側都要留
     │                 │
```

| 禁區 | 深度 | 擋誰 |
|---|---|---|
| 門的開啟弧線 | 半徑 = 門寬 | 所有傢俱（推拉門沒有這一項） |
| 開口兩側通行空間 | 60 cm | 所有落地傢俱 |
| 窗前採光帶 | 40 cm | 只擋高傢俱（衣櫃、冰箱） |
| 門洞／窗洞本身 | 25 cm | 壁掛物（電視不能掛在門上） |

**廚房檯面不算高傢俱**——那是下櫃，本來就該擺在窗下。
**壁掛電視不佔通行空間**——它掛在牆上，人從它前面走得過去。

由此推得幾個房間的硬下限：

- 一字型廚房淨深 ≥ **120 cm**（檯面 60 + 對側通行 60）
- 獨立淋浴間的衛浴淨深 ≥ **150 cm**（淋浴 90 + 通行 60）。約 1 坪的衛浴放不下，
  台灣的做法本來也是淋浴不做乾濕分離隔間。
- 主臥要同時放雙人床與衣櫃，淨深 ≥ **250 cm**、淨寬 ≥ **240 cm**

## 把門推到牆的一端

這是最有效的一招。門開在牆中央會把整面牆切成兩段短的：

```
門在中央                      門推到一端
├──120──┤門├──120──┤          ├門├────270────┤
 兩段都放不下 180 的衣櫃         留得下整組傢俱
```

用 `at`（0..1）控制。`at: 0.85` 幾乎貼著牆尾，`at: 0.5` 是最糟的選擇。

## 修改既有平面圖

改 spec，不要改展開後的 floorplan.json。

- **主臥加 50cm**：找到主臥所在節點的 `ratios`，把它那一份增加 `50 / 該層總長度`，
  其餘等比縮減。展開後量一下確認。
- **加一個陽台**：把某個葉子換成一個 `stack` 節點，底下掛原房間 + 新陽台。
- **開放式廚房**：把 `kitchen` 與 `living_room`／`dining_room` 之間的門改成
  `"type": "opening"` 並加大寬度。不要直接刪掉那道門——刪門會讓廚房從大門走不到，
  validator 的連通檢查會擋下來。也**不要**用加寬的 `sliding` 代替：那會畫出
  兩片不存在的門扇（規範裡「出入口」與「拉門」是兩個不同的符號，p23 表 8）。
- **刪掉書房**：移除該葉子，並把它的 ratio 併給兄弟節點；同時刪掉指向它的門窗傢俱熱區。

## 常見錯誤

| 展開器訊息 | 真正的意思 |
|---|---|
| 沒有共用牆段 | 這兩間房根本不相鄰。加一條走道，或調整切割順序讓它們相鄰。 |
| 共用段只有 N cm | 相鄰邊太短。放大其中一間，或縮小門寬。 |
| 房間 X 沒有貼到 N 側外牆 | 該房不在外框那一邊，開不了窗。它是暗房。 |
| 展開後尺寸為零 | ratios 給了太小的值，或切太多刀。 |
