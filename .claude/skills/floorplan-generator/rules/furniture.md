# 傢俱

傢俱是教學示意，不是 BIM。目的是讓使用者一眼看出「這是臥室」而不是「這是一個方框」。

## 型錄（單位 cm）

`width` 是靠牆的那一邊，`depth` 是伸進房間的那一邊。

| type | width × depth | 圖層 | 備註 |
|---|---|---|---|
| `sofa` | 220 × 90 | FUM | |
| `bed` | 152 × 188 | FUM | 標準雙人 5×6.2 尺 |
| `single_bed` | 91 × 188 | FUM | 標準單人 3×6.2 尺 |
| `dining_table` | 140 × 80 | FUM | 四人 |
| `chair` | 45 × 45 | FUM | |
| `desk` | 120 × 60 | FUM | |
| `wardrobe` | 180 × 60 | **FUF** | 當成系統櫃 |
| `tv` | 120 × 15 | FUM | |
| `kitchen_counter` | 240 × 60 | **FUF** | 一字型 |
| `toilet` | 40 × 70 | **FUF** | |
| `sink` | 60 × 50 | **FUF** | |
| `bathtub` | 150 × 70 | **FUF** | |
| `shower` | 90 × 90 | **FUF** | |
| `refrigerator` | 70 × 70 | FUM | 家電，搬得走 |

型錄以外的 type 必須自己給 `width` 與 `depth`，否則展開器會報錯。

## 固定家具 FUF 與活動家具 FUM

《室內設計裝修製圖規範》p46 表 23 把家具分成**兩個圖層**：
**07 活動家具 `FUM`**、**08 固定家具 `FUF`**。renderer 會照上表把 `data-layer`
掛在每一件家具的 `<g>` 上（對應 `render_svg.py` 的 `FIXED_FURNITURE`），viewer 可以直接拿去分層開關。

**這對買房教學特別有意義：交屋時「附不附」看的就是這條線。**
系統櫃、廚具、衛浴設備通常隨屋走；沙發、床、餐桌、冰箱通常不會。

**注意這與「三類特殊傢俱」是兩條不同的軸**，不要混在一起：

| 分類軸 | 用途 | 成員 |
|---|---|---|
| `FUF` / `FUM` | **畫在哪個圖層**（附不附） | 見上表 |
| `TALL` / `WALL_MOUNTED` / `FREESTANDING` | **碰撞規則**＋**畫成 X 還是虛線** | 見「三類特殊傢俱」 |

一件家具會同時有這兩個屬性：衣櫃是 `FUF`（固定）也是 `TALL`（畫 X）；
電視是 `FUM`（活動）也是 `WALL_MOUNTED`（畫虛線）。

## 擺放

```jsonc
{ "id": "f-bed-m", "type": "bed", "room": "room-master",
  "anchor": "n",     // 背靠房間的哪一面牆；center = 置中不靠牆
  "at": 0.45 }       // 沿該面牆的相對位置（傢俱中心），0..1
```

**`anchor` 與 `at` 是期望值，不是命令。** 展開器會在避開門的開啟弧線、開口通行空間、
窗前採光帶與其他傢俱的前提下求解：先沿指定的牆滑動找最近的空位，找不到就換一面牆，
換到哪面牆會印出 `↻` 訊息。加 `"strict": true` 可以禁止換牆（只在刻意示範某個問題時用）。

這跟「模型不寫座標」是同一個道理：你負責說出意圖（床要靠牆、電視對著沙發），
程式負責算出一個不會撞到門的位置。

`anchor` 決定旋轉與 AABB：

| anchor | 佔用的 bbox | rotation | 面向 |
|---|---|---|---|
| `n` | width × depth | 0 | 南 |
| `s` | width × depth | 180 | 北 |
| `w` | depth × width | 90 | 東 |
| `e` | depth × width | 270 | 西 |
| `center` | width × depth | 0 | — |

**`w` / `e` 會把長邊轉到垂直方向。** 這是最常見的踩雷點：一張 188cm 長的床
靠東牆擺，需要房間的**南北向**淨長 ≥ 188，而不是東西向。

## 三類特殊傢俱

| 類別 | 成員 | 碰撞規則 | 畫法 |
|---|---|---|---|
| 高傢俱 `TALL` | `wardrobe`、`refrigerator` | 會擋住窗戶採光，不得放在窗前 40cm 內 | 矩形內畫 **X** |
| 壁掛 `WALL_MOUNTED` | `tv` | 不佔地面通行空間，但不得掛在門洞／窗洞上 | **虛線**矩形 |
| 可置中 `FREESTANDING` | `dining_table`、`chair` | 只有這兩者可以擺在房間中央；其餘一律靠牆 | 一般實線 |

**畫法那一欄不是裝飾。** 平面圖是離地 120~150cm 平切下視，高櫃被切到所以畫 X、
壁掛物在切面以上所以畫虛線——完整理由見 `rules/geometry.md`。
換句話說，你在這裡選的類別會同時改變「它能不能放這裡」與「它在圖上長什麼樣」。

`kitchen_counter` 刻意**不算**高傢俱——那是下櫃，擺在窗戶下面是正常做法。
冰箱找不到牆就報錯，不會被丟到廚房正中央。

## 三個最常見的錯誤

**① 兩件大傢俱靠相鄰的兩面牆 → 在角落相撞**

床靠西牆、衣櫃靠北牆，兩者都會延伸到西北角。改成靠**對面**的牆
（床靠北、衣櫃靠南），或把其中一件的 `at` 推到另一端。

**② 房間淨寬不夠讓兩件並排**

主臥淨寬 244cm，床橫擺佔 188cm，只剩 56cm——放不下 60cm 深的衣櫃。
解法是把床改成直擺（`anchor: "n"`），讓短邊 152cm 靠牆，空出 92cm。
先算再擺，不要試。

**③ 靠牆方向選錯，傢俱比房間還長**

`shower` 90×90 沒差，`kitchen_counter` 240×60 差很多。
廚房淨深只有 155cm 時，檯面只能 `anchor: "n"` 或 `"s"`，不能 `"w"` / `"e"`。

## 放不下的時候

展開器會直接告訴你每一面牆還剩多少：

```
✗ 傢俱 f-wardrobe-m（wardrobe，180x60）放不進 主臥。房間淨空間 342x291，
  扣掉門的開啟弧線與開口兩側 60cm 通行空間後：
  北牆可用 122cm／需要 180cm；東牆可用 45cm／需要 180cm；
  南牆可用 95cm／需要 180cm；西牆可用 0cm／需要 180cm。
```

依序試這三招：

1. **把門的 `at` 推到牆的一端**——最有效，常常一次解決（見 `rules/geometry.md`）
2. **換小一點的傢俱**——衣櫃 180 → 150、書桌 120 → 100，都是真實尺寸
3. **調大該房的 `ratios`**——如果房間本來就低於 `rules/rooms.md` 的下限

**不要靠刪傢俱來消 error。** 那是把「圖畫錯了」換成「圖畫少了」。

## validator 會抓什麼

擺放階段已經避開的東西，validator 會再驗一次（防止展開器自己壞掉）：

- 傢俱超出房間 `inner`、傢俱互相重疊 → **error**
- 門開啟時撞到傢俱 → **error**
- 開口兩側通行空間被擋住 → **error**
- 高傢俱擋住窗戶、壁掛物掛在門洞上 → **error**
- 大型傢俱佔滿後通行淨寬 < 60cm → warning

## 建議配置

| 空間 | 放什麼就夠了 |
|---|---|
| 客廳 | `sofa` + `tv`（對牆） |
| 餐廳 | `dining_table`（`center`） |
| 廚房 | `kitchen_counter` + `refrigerator`（分開兩側） |
| 主臥 | `bed` + `wardrobe`（對牆） |
| 次臥 | `single_bed` + `desk`（對牆） |
| 衛浴 | `toilet` + `sink` + `shower`（三面分開） |
| 陽台 | 不放 |

不要為了填滿房間而塞椅子。傢俱越多，重疊的機會越大，教學價值卻沒有增加。
