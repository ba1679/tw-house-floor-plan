# 拼厝 Phin-Chhù｜建案平面圖教學網站

把平面圖裡的格、線與空間，慢慢拼成對家的理解。

**拼厝**是為台灣一般買房者設計的繁體中文學習網站。你可以在教學平面圖上點選符號，查閱白話解釋與出處，再透過練習確認自己是否認得；也可以學習分辨家具示意、尺寸依據，以及看屋時還需要向建商追問的資訊。

網站以手機使用為優先，也支援桌面瀏覽器、鍵盤操作與讀螢幕軟體。不需要註冊帳號。

**[前往拼厝網站](https://tw-house-floor-plan.vercel.app/)** · [在本機執行](#在本機執行)

## 可以用它做什麼？

| 功能 | 使用方式 |
| --- | --- |
| 互動看圖 | 從完整格局認識牆、柱、門窗與家具，點選圖上的位置查看說明。 |
| 查找符號 | 搜尋符號名稱或別名，或從「結構」「門窗」「家具家配」分類瀏覽。 |
| 查閱出處 | 在符號頁查看畫法、白話解釋、容易混淆的符號與文件出處。 |
| 找找看 | 依題目在平面圖中找出符號，查看答案與這張格局的學習進度。 |
| 學看家具與尺寸 | 跟著四步導讀，辨認圖上已知條件、尚缺資訊與可追問的問題。 |
| 換圖練習與提問清單 | 完成另一張局部圖的三題練習，或直接列印四項提問帶去看屋。 |

目前收錄一個「三房兩廳」完整教學格局、14 個符號，以及家具與尺寸的局部教學圖。範例由專案資料產生，沒有對應特定建案。

## 網站使用方式

### 1. 從格局開始看

在首頁選擇「三房兩廳」的看圖入口：

1. **先點大概位置**：網站會放大附近區域，圈出可選的候選熱區。
2. **再點要看的符號**：確認後開啟說明卡，顯示名稱與白話解釋。
3. 想看完整出處時，從說明卡前往符號頁。同一符號有多處時，可以切換到下一處。
4. 點錯區域時使用「重選」；自由看圖放大後，可使用「回到全圖」恢復視野。

自由看圖支援拖曳平移、雙指縮放與雙擊放大。使用鍵盤時，以 `Tab` 移動到熱區，按 `Enter` 或空白鍵直接開啟說明；`Esc` 可取消候選選取或關閉說明卡。

### 2. 從看不懂的符號開始查

在首頁或分類頁搜尋名稱、別名，也可以先選分類。符號頁會提供：

- 符號的畫法與白話意思。
- 容易認錯的符號，以及兩者差異。
- 已有資料支持的看屋注意事項。
- 來源層級與完整出處；若經由其他文件轉載，會列出轉載說明。
- 前往教學格局的入口，並標出該符號的位置。範例圖沒有呈現的符號會另行說明。

「國家標準」「法規」「業界慣例」「各家不同」描述的是**來源層級**。請搭配出處閱讀；經轉載取得的資料，不代表本站已核對標準原文。

### 3. 用「找找看」練習辨認

從首頁或格局頁進入「找找看」，按下開始後，依題目在圖上找出符號。點選仍採兩段式操作，確認選擇才算作答；同一符號在圖上的任一處都可作為答案。

每題作答後可查看答案與說明，再按「下一題」繼續。測驗期間的手動平移與縮放會鎖定，第一段點選仍會自動放大。完成後可查看本局結果，再玩一次。

學習進度儲存在**目前瀏覽器的 localStorage**，不會跨裝置同步。清除網站資料、換瀏覽器或使用無法保存資料的環境，可能讓進度消失；仍可繼續使用網站。

### 4. 學看家具與尺寸

從首頁進入「學看家具與尺寸」，依序閱讀四步：

1. **家具示意**：圖上畫有床，還需要什麼才能判斷自己的床放不放得下？
2. **尺寸依據**：尺寸線兩端量的是哪裡，能不能當作房間淨尺寸？
3. **使用空間**：除了放入家具，走動、開門與使用衣櫃還需要哪些空間？
4. **怎麼追問**：把缺少的資訊轉成可向建商詢問的具體問題。

每一步都能展開「看這一步的依據」，或回到完整格局核對。最後可換圖完成三題練習，選擇答案並確認後閱讀回饋；也可直接開啟「可列印提問清單」，透過瀏覽器列印或另存 PDF，不必先完成練習。

## 教學範圍

本站協助讀者辨認符號、理解圖面依據與資訊缺口。範例不是實際建案的實測圖，圖中的家具與留白也不能直接證明自己的家具放得下、通道足夠或符合特定要求。看屋時仍應核對該案圖面、標示尺寸、文件與自己的使用條件。

目前沒有上傳自有平面圖、AI 辨識或帳號同步功能。

## 在本機執行

需要 Node.js **20.9 以上**、npm，以及可用 `python3` 呼叫的 Python 3。CI 目前使用 Node.js 20；資料驗證使用 Python 標準函式庫。

```bash
git clone https://github.com/ba1679/tw-house-floor-plan.git
cd tw-house-floor-plan
npm ci
npm run dev
```

開啟 [http://localhost:3000](http://localhost:3000)。一般本機開發不需要 API 金鑰、資料庫或環境變數。

| 本機頁面 | 用途 |
| --- | --- |
| [首頁](http://localhost:3000) | 格局、搜尋、分類與學習入口 |
| [三房兩廳](http://localhost:3000/layouts/3b2l_standard) | 自由看圖 |
| [找找看](http://localhost:3000/layouts/3b2l_standard/quiz) | 符號辨認測驗 |
| [窗的符號頁](http://localhost:3000/symbols/window) | 符號內容與出處範例 |
| [家具與尺寸導讀](http://localhost:3000/guides/furniture-dimensions) | 四步導讀 |
| [換圖三題練習](http://localhost:3000/guides/furniture-dimensions/practice) | 圖面判讀練習 |
| [可列印提問清單](http://localhost:3000/guides/furniture-dimensions/questions) | 看屋提問與列印 |

### 建置與預覽

```bash
npm run build
npm run start
```

`build` 會先產生品牌資產、驗證內容與平面圖資料，再由 Next.js 匯出靜態網站到 `out/`。`start` 使用專案的靜態檔案伺服器預覽 `out/`，預設埠號為 3000，可用 `PORT` 覆寫。

### 部署設定

網站採 Next.js App Router、React 與 TypeScript，以 SSG 產生頁面，執行期不需要 API 或資料庫。部署時建置指令為 `npm run build`，靜態輸出目錄為 `out/`；使用其他靜態主機時，需支援將 `/symbols/window` 這類路徑對應至匯出的 `.html` 檔。

| 環境變數 | 用途 |
| --- | --- |
| `SITE_URL` | 建置時設定網站的完整正式網址，用於 canonical、Open Graph 與 sitemap。 |
| `VERCEL_PROJECT_PRODUCTION_URL` | 未設定 `SITE_URL` 時，採用 Vercel 提供的正式網域。 |
| `NEXT_PUBLIC_GA_MEASUREMENT_ID` | 選填。設定後載入 GA4 並傳送瀏覽與互動事件；未設定時不啟用。 |
| `PORT` | 本機開發、靜態預覽與 Playwright 測試使用的埠號。 |

未設定正式網址時會退回 localhost，因此正式部署前應設定 `SITE_URL` 或確認 Vercel 網域設定。這些建置設定變更後需要重新建置。

學習進度保留在瀏覽器；若部署者啟用 GA4，另外會記錄瀏覽與互動事件。搜尋事件會將未辨識的文字轉為 `other`，不傳送原始搜尋文字。分析設定與人工驗收項目見 [GA4 發布清單](docs/release/ga4-m6-checklist.md)。

## 驗證與測試

```bash
npm run typecheck          # TypeScript 型別檢查
npm run validate           # 符號、來源、導讀與練習資料驗證
npm run validate:floorplan # 平面圖幾何、參照與住宅領域規則驗證
npm run test:domain        # Python 領域規則測試
npx playwright install chromium
npm test                  # Playwright 測試，會自動建置並啟動靜態網站
```

Linux CI 可改用 `npx playwright install --with-deps chromium` 安裝瀏覽器及系統相依套件。執行 Playwright 前，請先停止同一埠號上的開發伺服器，以免重用到其他網站版本；也可以指定另一個 `PORT` 執行。

另有 `npm run audit` 執行 Lighthouse 行動版檢查，需要 Chrome／Chromium；必要時以 `CHROME_PATH` 指定瀏覽器執行檔。完整 CI 流程見 [M5 release gate](.github/workflows/m5-release-gate.yml)。

## 專案結構與維護

```text
app/          網站路由、頁面與全站樣式
components/   平面圖繪製、熱區互動、說明卡、搜尋與練習介面
lib/          圖面資料載入、互動狀態、測驗、內容與分析邏輯
data/         符號、格局原始描述、產生的平面圖、導讀與練習內容
scripts/      資料驗證、品牌資產產生、靜態預覽與 Lighthouse
tests/        Playwright 測試
public/       品牌等靜態資產
docs/         領域決策、查證報告與發布紀錄
design/       設計參考與原型
.scratch/     功能規格與實作票
.claude/skills/  建置仍會使用的平面圖產生器與領域驗證工具
```

平面圖的資料流為：**Layout 格局描述 → FloorPlan 平面圖資料 → SVG Renderer → Hotspot 熱區 → 互動狀態與說明卡**。請修改格局原始描述後重新產生平面圖，避免手動修改 `*.floorplan.json` 造成資料分岔；`.claude/skills/` 中的產生器與驗證器是現有建置的相依項目。

- [CONTEXT.md](CONTEXT.md)：符號、格局、平面圖、熱區等領域詞彙。
- [DESIGN.md](DESIGN.md)：介面設計語言與規則，調整畫面前先讀。
- [產品規格](平面圖教學網站-PRD-Phase1.md)：Phase 1 的產品背景與規格；目前功能仍應搭配程式與各功能票確認。
- [架構決策](docs/adr/)：既有做法與取捨理由。
- [工作票規則](docs/agents/issue-tracker.md)：`.scratch/` 的規格與議題管理方式。

回報內容或操作問題時，請附上頁面路徑、符號名稱、重現步驟與裝置／瀏覽器；內容更正若有文件依據，請一起提供文件名與頁碼或條次。請避免提交個人資料或未取得分享許可的實際建案圖面。
