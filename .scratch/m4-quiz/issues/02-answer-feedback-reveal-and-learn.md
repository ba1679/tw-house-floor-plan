# 02: 作答之後——答案標出來、答錯當場學

**What to build:** 題目是窗，他點到了柱。圖上 9 扇窗全部標出來，他點到的那根柱也留著標記——他分得出自己是點歪還是認錯。說明卡直接打開**窗**的說明，第一句是「你點的是柱」。他關掉卡片再看一眼圖，標記還在；按「下一題」才清掉。

答對的話，他點的那扇窗打勾，**另外 8 扇也標出來**——主圖的窗畫了三種，他剛剛認得的只是其中一種。說明卡不自動彈出，想看再按「看說明」。

**Blocked by:** 01（一局要先玩得動，才有「作答之後」）

**Status:** done

規格：`.scratch/m4-quiz/spec.md` 的「作答之後、按『下一題』之前」。

## 注意

- **暫停的形狀、說明卡由外部指定符號，照 01 動手前那次 `/codebase-design` 的結論做。** 若那次決定新增 stage 或外包一層而還沒寫 ADR，這張補上（難逆、會被問、有具體被拒絕的替代方案）
- **`revealed` 不是 `highlighted`**：形狀相同（一個符號的每一處），壽命不同——`highlighted` 在使用者開始選東西時就清掉（ADR-0006），`revealed` 留到按「下一題」。不得共用同一個欄位或同一個畫面狀態值，畫面上也要分得出來：從符號頁帶著高亮進平面圖的人，不該以為自己在答題
- **關閉說明卡在自由看圖 = 回到 browsing；在找找看不是。** 關掉卡片不清標記、不解除暫停
- **「下一題」一定收起說明卡，展開著也收。** 帶著展開的卡進下一題，就是 M2 票 08 修過的那個情境（卡片展開時 fit 很小，第一段的定位會被夾回圖中央），而鎖定視野時連補救的平移都沒有。07 刪測試靠的就是這一條
- **差異句**取**題目那一側** `confused_with` 那一筆的 `difference`；題目的 `confused_with` 裡沒有被點中的符號，就只有「你點的是 X」。**不為此補登資料**：圖上最常點錯的柱與相鄰的窗是位置相鄰、不是畫法相似
- **說明卡的出現次數只留「共 N 處」**：每一處已經都標在圖上，而答錯時 `selected` 不是那個符號，「第 M 處」數不出來
- **房間變暗**（說明卡開著時，M2 票 07）：有 `selected` 或 `revealed` 熱區的房間亮，其餘暗。照自由看圖只亮被點中那一間的規則，答錯時題目符號所在的房間反而會被壓暗

## Acceptance criteria

- [ ] 答對：被點中的是 `selected`，題目符號的其餘各處是 `revealed`；說明卡沒有自動打開
- [ ] 答對後按「看說明」：打開題目符號的說明卡，**沒有**「你點的是」那一句
- [ ] 答錯：題目符號的每一處是 `revealed`，被點中的是 `selected`；說明卡自動打開且顯示題目符號；卡上有「你點的是 X」
- [ ] 答錯且 X 在題目的 `confused_with` 裡（例：題目柱、點牆）→ 卡上有那一筆 `difference` 原文；不在裡面（例：題目窗、點柱）→ 沒有差異句
- [ ] 找找看的說明卡有「這張圖上共 N 處」，沒有「目前第 M 處」，也沒有「看它在圖上的其他位置」
- [ ] 作答後：點圖、雙擊、雙指、拖曳、鍵盤 Enter／空白鍵都不改變任何熱區的狀態
- [ ] 關閉說明卡後、說明卡升降使框高度改變後：`selected` 與 `revealed` 都還在，仍在暫停
- [ ] 「下一題」：標記清掉、題號前進、視野回到全圖、暫停解除；說明卡在展開狀態下按「下一題」也會收起
- [ ] 答錯時，有 `revealed` 熱區的房間沒有被壓暗
- [ ] `revealed`、`highlighted`、`candidate`、`selected` 四者的 computed style 彼此不同
- [ ] 平面圖頁自由看圖的行為不變：關卡片仍回到 browsing、說明卡仍有「第 M 處」與切換鍵（既有測試維持綠）

**2026-09-14：`/codebase-design` 給這張的兩個結論。** 模組怎麼切已經在 01 落地（見 01 的 Comments），這張照著長。

### 暫停由一局那一層管（`docs/adr/0007`）

01 的一局已經會認作答，暫停期間也不收 action。這張再加以下幾件。

**說明卡的開關進一局**
- 一局多一個 `sheetOpen`：作答答錯時設成開，答對時不開；`NEXT` 一律設成關。
- `OPEN_SHEET`（「看說明」）與 `CLOSE_SHEET`（卡片的關閉鍵、Esc）只在 `answered` 有作用。
- **關卡片不派 `RESELECT`**，那是自由看圖的關法。

**標記由一局交給框**
- `answered` 時，`selectedHotspot` 是最後一筆作答的 `hotspotId`，`revealedSymbol` 是它的 `target`；其餘時候兩個都是 null。
- 框因此多這兩個輸入。自由看圖傳 `viewer.selected?.id` 與 null。
- `data-state` 的優先序：`selected` > `candidate` > `revealed` > `highlighted` > `normal`。後三者不會同時出現在同一張圖上，排這個順序只是讓同一條式子兩頁都能用。

**框多一個 `paused`**
- 暫停期間檢視器是閒著的：01 在作答那一刻就把它退回 browsing，所以 `data-stage` 是 `browsing`。
- browsing 下那層「這裡可以點」的淡藍底色與 hover 不認得暫停。不處理的話，其餘熱區會在一張點不動的圖上全部亮起來。

**房間變暗，一條規則兩頁通用**
- 說明卡開著時，有 `selected` 或 `revealed` 熱區的房間亮，其餘暗。
- 自由看圖只有 `selected`，結果與現在相同；沒有任何標記落在房間裡時不壓暗，這點也與現在相同。

**框的寬度變了（手機轉橫）**
- 檢視器照舊退回 browsing，標記不受影響，因為它們不在檢視器裡。
- 票面只要求高度改變時標記仍在，寬度這一條是順帶得到的。

### 說明卡由外部指定符號

**`InfoSheet` 本來就接收 `symbol` 這個輸入。** 把卡片和 `selected` 綁在一起的，是自由看圖那一側「由 `selected` 推出卡片符號」的那一行；
01 拆完之後，那一行只留在自由看圖那一側。找找看那一側給的是**題目符號**。卡片本身要改的是另外幾個輸入：

- **出現次數改成兩種形狀擇一**：
  - `{ total, index, onNext }`：自由看圖用，有「第 M 處」與切換鍵。
  - `{ total }`：找找看用，只有「共 N 處」。

  現在分開的 `occurrence` 與 `onNextOccurrence` 併成一個，「有第 M 處卻沒有切換鍵」這種組合就寫不出來。
- **卡片最上面可以多一句，內容由頁面給**：找找看答錯時是「你點的是 X」，後面視情況接差異句。
  差異句只查**題目**的 `confused_with`（找被點中的那個 id），在找找看那一側算好再交給卡片；卡片不必知道什麼是作答。
- **`onClose` 本來就由外部給**：自由看圖接 `RESELECT`，找找看接 `CLOSE_SHEET`。
- **N = 1 的時候**：自由看圖那一列在 N = 1 時整列不出現（M2 票 03 決議 2，理由是卡片高度）。
  找找看「只有共 N 處」那一行在 N = 1 時要不要印，票面沒說；可出題的 13 個符號裡有 4 個只有 1 處：

### 做了什麼

- **一局**多一個 `sheetOpen`：
  - 答錯時開，答對時不開。
  - `OPEN_SHEET`、`CLOSE_SHEET` 只在 `answered` 有作用。
  - `NEXT` 一律設成關。
- **框**多三個輸入：`selectedHotspot`、`revealedSymbol`、`paused`。
  - `data-state` 的優先序照上面：selected > candidate > revealed > highlighted > normal。
  - 暫停時熱區層帶 `data-paused`，「這裡可以點」的底色與 hover 收起來。
  - 房間變暗改成「有 selected 或 revealed 熱區的房間亮」。`roomOfHotspot` 換成 `roomsWith`。
- **`revealed` 的畫法**：紫色虛線。
  - 色相避開高亮的黃、候選的藍、選中的紅。
  - 虛線是給分不出顏色的人的：靠線型也分得開。
- **說明卡**：
  - 出現次數併成一個輸入 `occurrence`，兩種形狀擇一：自由看圖傳 `{ total, index, onNext }`，找找看傳 `{ total }`。
  - 卡片最上面可以多一段 `note`：找找看答錯時是「你點的是 X。」，後面視情況接題目那一側的差異句。
- **作答後那一列**：「下一題」加「看說明」，「看說明」在卡片開著時不出現。Esc 關卡片。
- **鍵盤焦點**（票 01 留下的）：用鍵盤作答、或按了「看說明」的人，焦點跟著走。
  - 答錯時進說明卡。
  - 卡片關了，落在「下一題」。
  - 按下「下一題」，落在新的題目上。
  - 用手指點圖的人不搬，理由同自由看圖。
- **07 刪測試的前提已經驗到**：「下一題」那條測試在卡片展開的狀態下按「下一題」，卡片收起、視野回到全圖、第一段照常。

### 順手修的 bug：框被壓成 0 高

- **症狀**：找找看頁答錯、把卡片展開、再按「下一題」，圖停在 `scale(0)`，回不來。「下一題」那條測試抓到的。
- **原因**：
  - 找找看頁比平面圖頁多兩列（題目、作答後那一列），卡片一展開就把框壓成 0px。
  - fit 是框高除以圖高，算出 0。之後的等比調整都是拿 0 去乘，框長回來那一次的比例又是除以 0。
- **修法**：`reduceViewer` 的 `RESIZE` 不收 0 寬或 0 高的框，留著上一個真的框。
  - 矮的螢幕上，平面圖頁也會踩到同一個坑。

### 留給規格主人：找找看頁卡片展開時，圖剩 0px

平面圖頁卡片展開時圖剩 74.8px，那是 `InfoSheet.module.css` 寫下的依據：「平面圖僅餘 84px，足夠維持位置感」。
找找看頁多了題目列與作答後那一列，量到的數字（375 × 812）：

| 狀態 | 框的高度 |
|---|---|
| 出題中 | 359.9px |
| 答錯，卡片開著 | 242.7px |
| 卡片展開 | 0px |

這張沒有改版面，理由：
- 卡片展開是讀者自己要讀完整內容。收合時標記都看得到。
- 怎麼擠出高度是版面的取捨，例如題目列與作答後那一列合併成一列。

建議併進 08 重畫設計稿時一起定。
