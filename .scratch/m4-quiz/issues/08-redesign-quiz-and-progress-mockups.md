# 08: 重畫找找看與學習進度的設計稿

**What to build:** 一份與 PRD v0.7 對得上的找找看設計稿，取代現在 `design/` 下那兩份早於 v0.4 的找找看與學習進度設計稿。

**Blocked by:** 09（照它定下的設計語言與 token 畫）——而且**不擋任何一張票**

**Status:** done —— 2026-09-19 畫完、寫回 `design/quiz/`；與現況不同的兩處開成票 10、11。

規格：`.scratch/m4-quiz/spec.md` 的「文案與畫面」；PRD §11 #29。

## 為什麼要重畫

現在的兩份設計稿畫於 2026-08-20，比 v0.4 砍符號、v0.5 定題數都早。上面有一局 8 題、撒水頭與偵煙器（v0.4 已砍出範圍）、20 格進度尺與「16 / 20」、「46 SVG 單位」（PRD v0.5 警告過的單位錯誤，實作照抄會讓容錯半徑失效）、獨立的進度頁、「只練這 4 個」按鈕。M4 的實作票刻意不以它們為驗收。

## 為什麼是 ready-for-human

視覺與版面的取捨要規格主人判斷，不是 agent 可以自己收斂的東西。

## 保留（舊稿裡仍然成立的）

- 出題 → 第一段放大 → 答對／答錯 → 結算的順序
- 回饋不用紅綠：綠色是房產行銷語彙，且對色覺障礙者無效
- 進度用刻度而不是百分比：使用者要數得出來還差幾個
- 成績不誇獎也不責備——這是工具，不是遊戲化產品

## Acceptance criteria

- [x] 學習進度併入找找看的**開場與結算畫面**，沒有獨立的進度頁
- [x] 題數、分母、符號清單照 PRD v0.7 與真資料：13 個可出題符號、一局 7 題、樑不出現
- [x] 答對：被點中的打勾，題目符號的其餘各處是 `revealed`；說明卡不自動打開、有「看說明」
- [x] 答錯：題目符號每一處 `revealed`、被點中的 `selected`；說明卡是題目符號，第一句「你點的是 X」
- [x] 說明卡只有「共 N 處」，沒有「第 M 處」與切換鍵
- [x] `revealed`、`highlighted`、`candidate`、`selected` 四種看得出不同
- [x] 平面圖頁的找找看入口不另起一列（ADR-0003）
- [x] 沒有「只練還不熟的」
- [x] 若新設計稿要求畫面與實作現況不同，另開實作票——這張只產出設計稿

## Comments

**2026-09-19：開畫前的討論與決議。**

### 局面變了

開票時設計稿應該走在實作前面，現在反過來：M4 票 01–07 已完成，設計語言 01、02 已落地、03 做了大半。上面的 AC 大半條，現行畫面已經滿足。這張剩下的價值是兩件：

1. 換掉舊稿（`Quiz.dc.html` 的 8 題、撒水頭、「46 SVG 單位」；`Progress.dc.html` 那頁不該存在的進度頁），免得有人照抄。
2. 補上實作跳過的版面判斷：spec 寫明「驗收不包含與設計稿一致」，開場與結算是照 token 排出來的，沒有人看過整體。

### 決議（規格主人，全照建議）

- **起點：照現況畫，標出要改的。** 從現行實作的樣子出發；跟現況不同的格子在畫布上標出來，每一處對一張實作票。
- **開場：「開始」移到數字與刻度下面。** 順序改成：「你認得 N / M」加刻度 → 「一局 N 題」加開始 → 還不熟、還沒遇到、已認識三份清單。
  - 理由：現在「開始」排在清單最後，在 375 × 812 上還不熟到 6 個左右就會掉出第一屏；而「一局 7 題。題目說…」那段是標題以外最大的字，夾在清單與按鈕之間，層級反了。清單是參考，不是開始前的必讀。
- **結算：刻度上這一局新填的格子換畫法，不加字。** 對應 story 34「看得到這一局帶來的變化」；現在只印更新後的數字，要記得開場是幾才看得出變化。
  - 不加一句話：這局沒有新認得的時候，就不會出現一句讀起來像責備的話。
  - 換什麼畫法照 `DESIGN.md`：介面不用彩色，要靠形狀或填色密度，灰階下分得出來。
- ~~**找找看的說明卡：只有一處的符號也印「共 1 處」。**~~ **同日撤回，維持 2026-09-14 的裁定：不印。**
  - 同一件事 2026-09-14 已經裁定過（M4 票 02 的 Comments：照 M2 票 03 決議 2 不印），理由是這一列約 43px，補回去每張卡都頂到 46dvh 的上限。討論時 agent 沒查到那段就問了，中間沒有新的理由。
  - 不必再回頭翻這個問題。

### 沒定、先不動

- 標題「三房兩廳找找看」底下緊接「這張三房兩廳你認得 N / 13」，重複一次「三房兩廳」。文案是 spec 定的，先不改。

### 不歸這張

- 出題時圖框貼著平面圖的比例，375 × 812 上圖下方空著約 300px；平面圖頁相同。這是檢視器的版面（ADR-0003），要動另外談。
- 設計語言 03 還沒做完的兩件（`normal`／`candidate`／`highlighted` 的線還一半壓在熱區裡；鍵盤焦點把 State 的線換掉）：稿子照定案畫，差異已記在 03 票，不重開。

### 怎麼畫

照票 09 的做法：用 `FloorPlanRenderer` 對 `3b2l_standard` 真資料畫，熱區座標取自 JSON，勾、角標、候選圈都在真實位置。375 × 812，大約十格：

1. 開場：有進度
2. 開場：第一次打開（0 / 13，13 個都在還沒遇到）
3. 第 1 題，含首次引導
4. 第一段放大：候選圈，狀態列只說數量
5. 答對：勾 + 其餘各處 `revealed`，說明卡未開，有「看說明」
6. 答錯、有差異句（題目柱、點牆）
7. 答錯、沒有差異句（題目窗、點柱）
8. 結算：有答錯，刻度標出這一局新填的格子
9. 結算：全部答對（沒有答錯清單，也沒有誇獎）
10. 入口：平面圖頁標題列、首頁
11. 四種 State 並排：`revealed`、`highlighted`、`candidate`、`selected`

檔案：新稿取代 `design/Quiz.dc.html`，刪掉 `design/Progress.dc.html`，`design/canvas.json` 跟著改。
