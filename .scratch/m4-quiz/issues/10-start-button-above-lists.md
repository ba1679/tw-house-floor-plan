## 為什麼

現在的開場由上而下是：數字與刻度 → 「認得」的定義 → 三份清單 → 開場那一句 → 「開始」。

- **「開始」會被清單推出第一屏。** 375 × 812 上，還不熟多到 6 個左右，按鈕就要往下捲才按得到。還不熟一列一個（「錯 N 次」靠右），是三份清單裡最佔高度的那一份。
- **層級是反的。** 開場那一句（「一局 7 題。題目說一個符號……」）是標題以外最大的字，卻夾在清單與按鈕之間。
- **清單是參考，不是開始前的必讀。** 開場同時是學習進度住的地方（PRD §6.6），但來這裡的人多半是要玩。

## 注意

- **只動順序，不動內容。** 清單的分組、排法（還不熟錯最多的在前）、「錯 N 次」、會折行的一串、文案，一律不變。
- **「讀到進度之前不印數字」的規矩不變**（票 05）。讀到之前只有開場那一句與按不下去的「開始」；讀到之後數字與刻度出現在上面，把按鈕往下推一段——但按鈕正是在同一刻才變得按得下去，所以不會有人按到一半被推走。票 05 把「開始」排在清單後面，理由就是這一條，新順序照樣守得住。
- `QuizGame.tsx` 裡講「清單出現、把按鈕往下推的那一刻」的那段註解，跟著改成新順序的說法。
- 「認得」的定義（`KNOWN_DEFINITION`）留在數字底下：它講的是那個數字。
