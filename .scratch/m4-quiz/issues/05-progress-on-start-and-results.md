# 05: 開場與結算看得到你認得幾個

**What to build:** 他打開找找看，第一眼是「這張三房兩廳你認得 9 / 13」，下面是還不熟的管道間（錯 2 次）、浴缸（錯 1 次），再來是還沒遇到的兩個。玩完一局，結算畫面告訴他答對 6 / 7、他把推拉門答成了窗——點那一列就到推拉門的符號頁再讀一次——以及更新後的「你認得 11 / 13」。他可以再玩一次，或回到平面圖。

**Blocked by:** 04（開場與結算要讀得到進度紀錄）

**Status:** ready-for-agent

規格：`.scratch/m4-quiz/spec.md` 的「學習進度」「一局的流程」；PRD §6.3.3、§6.6。

## 注意

- **沒有獨立的進度頁**：想知道自己還差什麼的那一刻，正是要開始玩的那一刻（PRD §11 #28）
- **分母是可出題符號數**，由資料算，與 01 的題數、題目池是同一個算法
- **靜態 HTML 不得先印出一個假的「0 / 13」再跳成真的數字**——那一瞬間的 0 就是進度條在說謊。分子與清單在讀到 localStorage 之後才出現
- **還不熟排在最前面**（錯最多的在前）：使用者來這裡是想知道還差什麼。「錯 N 次」與「還沒遇到」是兩種不熟，要分得出來
- **答錯清單的「你答成了 X」**要記住這一局每一題被點中的符號——只在記憶體裡，不進 localStorage（04 的紀錄格式不變）
- 答錯的符號文案寫「**之後**會再出現」，不承諾下一局：出題優先的是還沒遇到的
- **不誇獎、不責備**
- 畫面照現有樣式做，**不以設計稿為驗收**（08 另外重畫）

## Acceptance criteria

- [ ] 開場：預塞的進度 → 「你認得 N / 13」正確；還不熟清單依錯誤次數排序並寫出次數；還沒遇到、已認識清單正確
- [ ] 開場：空紀錄 → 0 / 13，13 個都在還沒遇到
- [ ] 讀取進度之前，建置產出的 HTML 裡沒有「你認得」的分子數字
- [ ] 13 / 13 時照樣可以按「開始」
- [ ] 結算：答對數 / 題數；答錯清單每一列有「你答成了 X」，並連到 `/symbols/{題目符號}`；「你認得 N / M」已經是這一局之後的數字
- [ ] 「再玩一次」依更新後的進度重新出題，回到第 1 題；「回到平面圖」到 `/layouts/{id}`
- [ ] localStorage 被封鎖時，開場與結算照樣顯示（當成空紀錄）
