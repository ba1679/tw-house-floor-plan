# 03: 作答之前不露名字

**What to build:** 用鍵盤作答的人按 Tab 走過主臥，聽到的是「主臥 · 第 3 個可以點的東西」，不是「窗」——題目不會被念給他聽。他答完這一題，Tab 一圈只聽得到**這一題**被點中與標出答案的那幾個名字；其他熱區仍然不說，他不會因此知道後面幾題的答案在哪。

**Blocked by:** 02（「作答後只放開 `selected` 與 `revealed`」要用到 02 做出來的 `revealed`；兩張也都改熱區怎麼畫，分開做會互相衝突）

**Status:** ready-for-agent

規格：`.scratch/m4-quiz/spec.md` 的「作答之前不露名字」；PRD §6.3.1、§9。

## 注意

- **範圍是使用者感知得到的管道**：畫面、狀態列、讀螢幕軟體念得出來的東西。熱區 id 照舊帶類型縮寫，要打開 DOM 才看得到，而找找看沒有排行榜、不防開發者工具——不改 id
- **k 是該熱區在它那一間房裡的閱讀順序**，也就是 Tab 走的 DOM 順序。房間內依類別排（結構 → 門窗 → 家具家配），會透露一點類別資訊，**spec 寫明接受**：改依座標就與 Tab 的順序對不上，要一致就得替找找看另算一套閱讀順序。聽得到替代文字的是讀螢幕使用者，而這個題型本來就不讓他們有意義地遊玩；看得見的鍵盤玩家看的是焦點框住的圖形
- **整局都中性，作答後只放開這一題的 `selected` 與 `revealed`**。全部恢復的話，Tab 一圈就知道後面題目的位置
- 用語沿用現有狀態列的「可以點的東西」；`CONTEXT.md` 的 Hotspot 避免用「標記」
- **自由看圖的替代文字照舊念符號名字**——只有找找看頁換
- **找找看頁不掛 `?symbol=` 高亮**：高亮把一個符號的每一處同時圈亮，就是把答案畫在圖上。若 01 的組法已經自然不掛，這張補測試釘住
- 讀螢幕使用者無法有意義地遊玩是題型本質（PRD §9 v0.7），不做替代玩法

## Acceptance criteria

- [ ] 作答前，每一個熱區的替代文字都不含任何符號名字，格式是「房間名 · 第 k 個可以點的東西」
- [ ] 作答後，只有 `selected` 與 `revealed` 的熱區替代文字含符號名字，其餘仍是中性；按「下一題」後全部回到中性
- [ ] 第一段圈出候選、點到空白處、第二段沒點中時，狀態列都不含任何符號名字
- [ ] 作答前沒有任何熱區是 `revealed`，也沒有其他能區分出題目熱區的狀態
- [ ] 找找看頁網址帶 `?symbol=window` 時不高亮任何熱區，也不出現「找不到網址指定的符號」
- [ ] 平面圖頁的熱區替代文字仍是符號名字（既有鍵盤測試維持綠）

## Comments

**2026-09-14：`/codebase-design` 給這張的結論。** 模組切法見 01 的 Comments。

**名字念不念：框收一個二選一的輸入 `names: "all" | "marked"`**
- 自由看圖傳 `all`。
- 找找看傳 `marked`：只有 `selected` 與 `revealed` 的熱區念名字，其餘念「房間名 · 第 k 個可以點的東西」。
- k 就是熱區在 `readingOrder` 那一間房裡的位置，框本來就照這個順序畫。
- **不改成收一個「給我每個熱區的替代文字」的函式。** 函式會讓每個呼叫端自己決定誰露名字，「作答後只放開這一題的」這條規矩就散到頁面各處去了。

**作答前沒有任何熱區是 `revealed`**
- 02 的標記只在 `answered` 時由一局交出來，所以這一條由結構本身保證。
- 這張補測試釘住。

**`?symbol=`**
- 01 的組法裡，網址高亮只掛在自由看圖那一側，找找看頁本來就不讀網址。
- 這張補一條測試：帶 `?symbol=window` 時不亮任何熱區，也不出現「找不到網址指定的符號」。

**狀態列**
- 兩段式進行中的三句寫在框裡，本來就是中性的。
- 作答前，找找看交給框的那一句（首次引導）也不含名字。
- 作答後可以說出被點中的符號名字（spec）。
