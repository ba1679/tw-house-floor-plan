# 06: 平面圖頁與首頁的找找看入口

**What to build:** 他在三房兩廳平面圖上點了一陣子，想測測自己，入口就在頁面上；第一次到首頁的人也看得到找找看的入口，可以直接從玩開始。從 Google 落在符號頁的人，看到的仍然只有那一顆「這個符號在真實格局裡長怎樣 →」。

**Blocked by:** 01（入口要有地方連）

**Status:** ready-for-agent

規格：`.scratch/m4-quiz/spec.md` 的「路由與頁面」；PRD §8。

## 注意

- **平面圖頁的入口不得讓檢視器的框變矮。** 那一頁是 100dvh 的版面，每一列都從平面圖的可視帶挖高度（ADR-0003）；平面圖頁的 `<h1>` 刻意不換成長標題就是同一個理由。擺在既有的列裡，不另起一列
- **首頁的入口與「開始探索」按鈕同樣由資料產生**，只替有可出題符號的 layout 產生，不寫死 `3b2l_standard`
- **符號頁不放**：它的轉換點是把搜尋流量帶進產品核心的唯一入口（PRD §6.2.1），不該被第二顆按鈕分散
- 文案進集中管理的文案模組

## Acceptance criteria

- [ ] 平面圖頁有一個連往該 layout 找找看頁的入口
- [ ] 加了入口之後，375 × 812 下檢視器的框高度與加之前相同——說明卡收合與升起兩種狀態都量
- [ ] 首頁每張有可出題符號的 layout 各有一個入口，連到對應的找找看頁
- [ ] 符號頁上沒有連往找找看頁的連結
- [ ] 既有首頁與平面圖頁的測試維持綠
