# 11: 結算的刻度標出這一局新填的格子

**What to build:** 一局打完，他看到「這張三房兩廳你認得 9 / 13」，刻度上有 5 格比其他格高一截——那是這一局新認得的。他不必記得開場是 4，也看得出這一局帶來了什麼。這一局沒有新認得的，刻度就只是沒有高出來的格子，畫面上不多一句話。

**Blocked by:** None（可以直接開始，與票 10 動的是同一個畫面的不同部分）

**Status:** done —— 2026-09-19 實作：結算的刻度把這一局新認得的格子加高一倍（B）；「留給規格主人」那一題同日定案、也做了（見 Comments）。

規格：`.scratch/m4-quiz/spec.md` user story 34（「結算畫面看到更新後的『你認得 N / 13』，so that 我看得到這一局帶來的變化」）；設計稿：`design/quiz/Q09-results.dc.html`（⑨ 結算：有答錯）、`Q10-results-all.dc.html`（⑩ 結算：全部答對）、`Q14-meter-options.dc.html`（⑭ 三種畫法，選 B）；規則：`DESIGN.md` 的「學習進度的刻度」；決議：票 08 的 Comments（2026-09-19）。

## 畫法（B，2026-09-19 選定）

- 這一局新填的格子**加高一倍**，照樣是墨色實心，與其他格**底部對齊**。其餘格子不變：已認識的墨色實心，還沒認得的 `--rule`。
- 新填的格子排在已認識那一段的最後面（刻度是數量，不是逐個符號對位）。
- **不加字、不換色、不用空心格**：介面不用彩色；空心會被讀成「還沒認得」（DESIGN.md）。
- **開場的刻度不分新舊**，只有結算畫。
- 值（高度）寫在 `components/Quiz.module.css`，不寫進 DESIGN.md。

## 注意

- **「新填」怎麼算**：結算時已認識、但這一局開始時還不是已認識的符號。兩端都用 `groupByFamiliarity` 問，而且問的是**同一個來源**：開始時讀到的那一份進度，以及 `useSaveAnswers` 寫完之後讀回來的那一份。不從這一局的作答另外推算——兩種算法在儲存被封鎖、或寫入失敗時會各說各話。
  - localStorage 被封鎖時兩端都是空紀錄，新填的是 0 格，數字也是 0：刻度與數字對得上。
- **開始時的那一份要從 `QuizGame` 交進 `QuizRound`**：`start()` 出題時已經讀過一次（`loadLayoutProgress`），就用出題讀到的那一份。「再玩一次」同樣走 `start()`，所以第二局的「開始時」就是第一局結束後的進度。
- 刻度是 `aria-hidden`（字已經說了數字），新填幾格同樣只在畫面上看得到。要不要替讀螢幕的人補一句，見下面「留給規格主人」。

## Acceptance criteria

- [x] 這一局沒有新認得的（例如全部答錯，或答對的都是已認識的）：沒有任何加高的格子，畫面上也不多任何字

- [x] 13 / 13 之後再打一局全對：沒有加高的格子（都已經認得了）
- [x] localStorage 被封鎖：結算「你認得 0 / 13」，沒有加高的格子，不丟例外
- [x] 「再玩一次」之後的結算，以第二局開始時的進度為準
- [x] `npm run typecheck`、`npm test` 通過

## 留給規格主人

- **讀螢幕的人聽不到這一局多認得了幾個。** 刻度是 `aria-hidden`，而這一次的決定是畫面上不加字。要不要給一句只有讀螢幕軟體念得到的話（例如「這一局新認得 5 個」）？加的話是新文案，要進 `lib/ui/copy.ts`，而且這一局沒有新認得時要不要說、怎麼說，同樣有「讀起來像責備」的問題。
