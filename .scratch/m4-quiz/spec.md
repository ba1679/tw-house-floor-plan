## Problem Statement

他在符號頁讀過「柱是深灰、牆是淺灰」，也在平面圖上點開過幾張說明卡。他覺得自己懂了。

但這個網站從來沒有**問過**他。檢視器只在他指著一個東西的時候告訴他那是什麼；他從來沒有被要求「自己把窗找出來」。等他拿到建商給的那張圖，才會發現「看過」與「認得」差很遠——而那時候已經沒有人可以問。

他也沒有辦法知道「這張圖我到底認得幾個」。能拿來當進度的只有「點開過幾張說明卡」，而那是一個會說謊的數字：看過不等於記得，這個網站的整個賣點卻是不說謊。

檢視器這一側也留著一件沒做完的事：M2 在狀態機裡預留了找找看的視野鎖定，但沒有任何畫面打開它，只有一個測試用的網址參數 `?fitLocked=1`——一個開在正式頁面上、能把圖鎖死、畫面上又沒有東西能解開的後門。

## Solution

每一張有可出題符號的格局圖，多一頁找找看。

打開它，先看到「這張三房兩廳你認得 N / 13」，以及還不熟、還沒遇到的符號清單。按開始，題目寫「找出這張圖上的窗」，圖固定在全圖、不能自己縮放。他照平常看圖的方式點：點大略位置、圖自動放大、再點一次確認——**那一下就是他的答案**，一題一次。

答對，他點的那扇窗打勾，圖上另外 8 扇窗也標出來——主圖的窗畫了三種，他剛剛認得的只是其中一種。答錯，9 扇窗全部標出來，他點到的那根柱也留著標記，說明卡直接打開窗的說明，第一句是「你點的是柱」。看完自己按下一題。

一局是可出題符號數的一半（主圖 7 題），所以打完兩局一定考遍每一個。考遍之後，還不熟的優先出。一局結束：答對幾題、答錯的清單（點進符號頁再讀一次）、更新後的「你認得 N / 13」。

進度只存在這台裝置上。「認得」只有一個定義：**在找找看裡答對過至少一次**。

## User Stories

1. As a 首購族, I want 從平面圖頁有一個入口進找找看, so that 我看完圖想測自己時不必另外找
2. As a 第一次到首頁的人, I want 首頁也有找找看的入口, so that 我可以直接從玩開始
3. As a 玩家, I want 一打開就看到「這張圖你認得 N / 13」, so that 我知道自己還差多少
4. As a 玩家, I want 開場看到還不熟與還沒遇到的符號清單, so that 我知道自己的弱點在哪
5. As a 玩家, I want 還不熟的排在最前面並寫出錯了幾次, so that 我知道哪些最該練
6. As a 玩家, I want 按「開始」才出第一題, so that 我看完進度再決定要不要玩
7. As a 玩家, I want 一局的題數是這張圖可出題符號的一半, so that 打完兩局就一定每個都考過
8. As a 玩家, I want 第二局優先考第一局沒考過的符號, so that 我兩局就能走完整張圖
9. As a 玩家, I want 每個符號都考過之後優先考我還不熟的, so that 練習花在刀口上
10. As a 玩家, I want 題目寫的是符號的正式名稱, so that 我在符號頁學到的名字就是題目上的名字
11. As a 玩家, I want 看得到現在是第幾題、共幾題, so that 我知道還剩多久
12. As a 玩家, I want 作答時圖固定在全圖、不能自己縮放或拖曳, so that 每個人面對的難度一樣
13. As a 玩家, I want 點大略位置時圖照樣自動放大, so that 我不必手指很準也能作答
14. As a 玩家, I want 圖放大後只告訴我圈出了幾個候選、不告訴我它們是什麼, so that 題目不會被說破
15. As a 玩家, I want 按「重選」、換個地方點都不算作答, so that 我可以在確定之前多看幾眼
16. As a 玩家, I want 第二段沒點中任何候選不算作答, so that 手滑不會直接被判錯
17. As a 玩家, I want 第二段確認的那一下就是我的答案、一題只有一次, so that 答對代表我真的認得
18. As a 玩家, I want 符號在圖上有多處時點中任何一處都算對, so that 考的是認不認得，不是猜不猜得到出題者心裡的那一個
19. As a 玩家, I want 答對時我點的那一處打勾, so that 我立刻知道對了
20. As a 玩家, I want 答對時這個符號在圖上的其他幾處也標出來, so that 我看到同一個符號的其他畫法
21. As a 玩家, I want 答對時不自動彈出說明卡、但有「看說明」可以按, so that 我已經會的東西不會被強迫再讀一次
22. As a 玩家, I want 答錯時正確答案的每一處都標出來, so that 我知道它到底長在哪裡
23. As a 玩家, I want 答錯時我點的那一個也留著標記, so that 我分得出自己是看錯還是點歪
24. As a 玩家, I want 答錯時直接打開題目符號的說明卡, so that 我在錯的當下就學
25. As a 玩家, I want 說明卡告訴我「你點的是 X」, so that 我知道自己把它當成了什麼
26. As a 玩家, I want X 正好是容易搞混的符號時，說明卡說出兩者差在哪, so that 我下次分得出來
27. As a 玩家, I want 說明卡告訴我這個符號在這張圖上共幾處, so that 我知道圖上標出來的就是全部
28. As a 玩家, I want 作答之後、按「下一題」之前點圖不會發生任何事, so that 我不會不小心把答案標記弄掉
29. As a 玩家, I want 關掉說明卡之後答案標記還在, so that 我可以不被卡片擋住地再看一次
30. As a 玩家, I want 自己按「下一題」而不是被計時器推著走, so that 我可以看清楚再走
31. As a 玩家, I want 一局結束時看到答對幾題, so that 我知道這局的結果
32. As a 玩家, I want 結算畫面列出答錯的符號與我當時答成了什麼, so that 我知道要回去複習哪些
33. As a 玩家, I want 點複習清單的一列就到那個符號的符號頁, so that 我讀得到完整的說明與出處
34. As a 玩家, I want 結算畫面看到更新後的「你認得 N / 13」, so that 我看得到這一局帶來的變化
35. As a 玩家, I want 「再玩一次」與「回到平面圖」兩個出口, so that 我決定接著練還是回去自由看圖
36. As a 玩家, I want 結算的文字不誇獎也不責備, so that 它像一個工具而不是一個討好我的遊戲
37. As a 玩家, I want 答對過一次的符號就算認得、只點開看過說明不算, so that 進度條不會說謊
38. As a 玩家, I want 點歪到別的符號不會讓那個符號被記成不熟, so that 我的清單反映的是我真的不認得的東西
39. As a 玩家, I want 每答一題就記下來, so that 我玩到一半離開時已經答的不會白答
40. As a 玩家, I want 中途離開不被確認視窗攔住, so that 我想走就走
41. As a 玩家, I want 全部認得之後還是可以玩, so that 我可以隨時複習
42. As a 用無痕視窗的人, I want 瀏覽器不讓網站存資料時照樣能玩, so that 我不會以為網站壞了
43. As a 從首頁直接進找找看的人, I want 看到與平面圖頁同一句兩段式點擊的引導, so that 我知道怎麼點
44. As a 已經在平面圖頁看過引導的人, I want 找找看不再重複那句引導, so that 同一件事不必教我兩次
45. As a 用鍵盤作答的人, I want 用 Tab 在熱區間移動、按 Enter 或空白鍵作答, so that 我不需要滑鼠也能玩
46. As a 用鍵盤作答的人, I want 熱區念出的是「主臥 · 第 3 個可以點的東西」而不是符號名字, so that 答案不會被念給我聽
47. As a 用鍵盤作答的人, I want 作答之後 Tab 一圈聽不到其他熱區的名字, so that 我不會因此知道後面幾題的答案在哪
48. As a 搜尋引擎, I want 找找看頁標記 noindex 且不在 sitemap 裡, so that 我不會收錄一頁沒有文字內容的空殼
49. As a 內容維護者, I want 題目、題數、進度分母全部由資料算出, so that 我加一個符號或一張圖時不必改程式
50. As a 內容維護者, I want 沒有任何可出題符號的圖不產生找找看頁, so that 不會有一頁打開就無題可出
51. As a 內容維護者, I want 答錯時的差異句直接取自 `confused_with`, so that 我改一次資料，符號頁、說明卡、找找看一起改
52. As a 開發者, I want 平面圖頁不再接受 `?fitLocked=1`, so that 正式頁面上沒有一個能把圖鎖死、又沒有 UI 解開的後門
53. As a 開發者, I want 找找看復用同一個檢視器與兩段式狀態機, so that 看圖與作答的手感只有一套
54. As a 開發者, I want 「一局出哪些題」是一個不碰 DOM、不讀 localStorage 的純函式, so that 真資料做不出來的形狀也測得到

## Implementation Decisions

### 路由與頁面

- **`/layouts/[id]/quiz`**，SSG。產生哪幾頁由「有可出題符號的 layout」決定：一張圖一個可出題符號都沒有，就不產生這一頁（取代 PRD 舊 schema 的 `quiz_enabled`）。與平面圖頁一樣 `dynamicParams = false`，**不寫死 `3b2l_standard`**
- 每頁自己的標題與描述，由 `floorplan.name` 生成，文案進集中管理的文案模組
- **`noindex`，不進 sitemap**。sitemap 那一側「有哪幾種頁」是手列的，這次刻意不加；它的網址數維持 19
- **入口**：平面圖頁一個、首頁每張有可出題符號的圖一個（與「開始探索」按鈕同樣由資料產生）。**符號頁不放**——它的轉換點（PRD §6.2.1）不該被第二顆按鈕分散
- 平面圖頁的入口**不得讓檢視器的框變矮**：那一頁是 100dvh 的版面，每一列都從平面圖的可視帶挖高度（ADR-0003；平面圖頁的 `<h1>` 刻意不換成長標題就是同一個理由）。擺在既有的列裡，不另起一列
- 找找看頁**不掛 `?symbol=` 高亮**。高亮會把一個符號的每一處同時圈亮，出現在找找看頁就是把答案畫在圖上

### 可出題符號、題數與出題（純函式）

- **可出題符號只有一個算法**：該 floorplan 上 `symbol_id` 非 null 的熱區，取不重複的 `symbol_id`。題目池、題數、進度分母、「這張圖產不產生找找看頁」四處都問它，不得各算各的（與 `hotspotsOfSymbol` / `isSymbolAbsent`「只有一種算法」是同一條規矩）
- **題數 = ⌈可出題數 ÷ 2⌉，不設上限**。主圖 13 → 7
- **出題**：輸入是可出題符號、這張圖的進度紀錄、一個亂數來源；輸出是這一局依序要出的 symbol id。
  1. 依熟悉度分三層：**還沒遇到**（correct 與 wrong 皆 0）→ **還不熟**（correct 為 0、wrong > 0，依 wrong 由多到少，同數隨機）→ **已認識**（隨機）
  2. 依層序填到題數為止
  3. 選出來的集合**整局打亂**再出
- 熟悉度**只由 `fp:progress:v1` 的次數算出**，不加欄位。紀錄裡有、但已經不是可出題符號的 id（例如日後資料改了）一律忽略
- 亂數來源由呼叫端傳入：頁面用 `Math.random`，測試傳固定序列
- 這個函式不碰 DOM、不讀 localStorage，放在 lib 層，與搜尋比對同一種定位

### 作答

- **作答 = 第二段確認了一個熱區，或鍵盤 Enter／空白鍵選定一個熱區**——也就是狀態機裡走到「選定一個熱區」的那兩條路。第一段圈出候選、「重選」、第二段沒點中（`confirmMissed`）都不是作答
- 出題期間視野鎖定用既有的 `SET_FIT_LOCKED`：擋使用者自己的縮放、平移、雙擊放大，不擋第一段的自動 3×、不擋「回到全圖」、不擋鍵盤焦點的自動平移（M2 已定案、已測）
- **判定**：被選定熱區的 `symbol_id` 等於題目的 symbol → 答對。一個符號多處時點中任一處都算對（PRD §6.3.2）

### 作答之後、按「下一題」之前

- **圖上的 State**（`CONTEXT.md`）：被點中的那一個是 `selected`；題目符號在圖上的其餘各處是 `revealed`（答錯時就是每一處）。`selected` 優先於 `revealed`
- **`revealed` 不是 `highlighted`**：形狀相同（一個符號的每一處），壽命不同——`highlighted` 在使用者開始選東西時就清掉（ADR-0006），`revealed` 留到按「下一題」。不得共用同一個欄位或同一個 `data-state` 值
- **圖暫停**：這段期間的 `TAP`、雙擊、雙指、拖曳、鍵盤 Enter／空白鍵都不改變任何事。「看說明」、「下一題」、說明卡的關閉與上拉照常。**關閉說明卡不得清掉標記、不得解除暫停**——自由看圖時關卡片等於回到 browsing，找找看不是
- 框的高度因說明卡升降而改變（`RESIZE`）時，標記與暫停都維持
- **按「下一題」**：收起說明卡（展開著也收）、清掉 `selected` 與 `revealed`、視野回到全圖、解除暫停。**收起說明卡是必要的**——帶著展開的卡進下一題，就是 M2 票 08 修過的那個情境（卡片展開時 fit 很小，第一段的定位會被夾回圖中央），而鎖定視野時連補救的平移都沒有
- **說明卡開著時的房間變暗**（ADR-0005、M2 票 07）在找找看裡改以「有 `selected` 或 `revealed` 熱區的房間」為亮、其餘變暗。照自由看圖的規則只亮被點中熱區的那一間，答錯時題目符號所在的房間反而會被壓暗
- **暫停做成什麼形狀不在這份 spec 決定**：它是自由看圖三個 stage 都沒有的行為，正好是 ADR-0006「什麼情況下該推翻它」寫的那一種——是狀態機的第四個 stage，還是找找看包在檢視器 reducer 外面的一層，由 `/codebase-design` 定，視結果補 ADR。這份 spec 只規定上面那幾條外部行為
- **答對**：不自動開說明卡。回饋列有「看說明」（開題目符號的說明卡，沒有「你點的是」那一句）與「下一題」
- **答錯**：自動打開**題目符號**的說明卡，卡片最上面多一句「你點的是 X」。題目符號自己的 `confused_with` 裡有 X 時，接上**題目那一側**那一筆的 `difference`；沒有就只有那一句。不為此補登資料
- **說明卡顯示哪個符號與 `selected` 在找找看裡是兩件事**：自由看圖時兩者永遠相同，找找看答錯時卡片是題目符號、`selected` 是被點中的另一個。說明卡要能由外部指定它顯示的符號
- 說明卡上的出現次數在找找看裡**只留「這張圖上共 N 處」**：不印「目前第 M 處」，不出「看它在圖上的其他位置」——每一處已經都標在圖上，而答錯時 `selected` 不是那個符號，「第 M 處」數不出來。N 照舊由 hotspots 算
- 狀態列在作答後可以說出被點中的符號名字（答案已經交出去了）

### 作答之前不露名字

規則（PRD §6.3.1）：**作答之前，畫面、狀態列、讀螢幕軟體念得出來的東西裡，都不得出現任何熱區的符號名字，也不得有能分辨出答案熱區的標示。** 題目文字本身當然寫出符號名字——那是題目。

範圍是**使用者感知得到的管道**，不是 DOM 的每一個屬性：熱區 id（例如 `hs-win-*`）照舊帶著類型縮寫，要打開 DOM 才看得到，而找找看沒有排行榜、不防開發者工具。改 id 會牽動 floorplan 資料與既有測試，換來的只是擋住一個不需要擋的人。

- **熱區替代文字**：`{房間名} · 第 {k} 個可以點的東西`（沿用現有狀態列「可以點的東西」的說法；`CONTEXT.md` 的 Hotspot 避免用「標記」），k 是該熱區在它那一間房裡的閱讀順序，也就是 Tab 走的 DOM 順序（已經依房間分段、在 build 時算好）。房間分組的標籤照舊
- **閱讀順序在房間內依類別排（結構 → 門窗 → 家具家配）、不在任何房間裡的熱區排最後——這會透露一點類別資訊，接受。**k 若改依座標，就與 Tab 的順序對不上（這一個念「第 3 個」、下一個念「第 1 個」）；要兩者一致就得替找找看另算一套閱讀順序。而聽得到替代文字的是讀螢幕使用者，這個題型本來就不讓他們有意義地遊玩（PRD §9）；看得見的鍵盤玩家看的是焦點框住的圖形，順序給不了他答案
- **整局都用中性標籤，作答之後也只放開 `selected` 與 `revealed` 那幾個**。若作答後把全部熱區的替代文字恢復成名字，鍵盤玩家 Tab 一圈就知道本局後面題目的位置
- 狀態列在第一段圈出候選時只說數量（現有的文案已經是中性的，保持）；點到空白處、第二段沒點中的提示同樣不含名字
- 作答前不得先在熱區上掛任何區分出題目的狀態（不得先掛一個看不見的 `revealed`）

### 學習進度

- key `fp:progress:v1`，schema 照 PRD §6.6.1 不變；`version` 不符時整份丟棄重來，不寫遷移
- **每作答一題立刻寫入**：答對 `correct[題目]++`，答錯 `wrong[題目]++`，更新 `updated_at`。**被點中的那個符號不記**
- localStorage 讀寫丟例外（瀏覽器封鎖儲存）時當作空紀錄：照樣出題、照樣作答，只是不記。M2 的首次引導已經有同樣的防護寫法
- **開場畫面**：「這張圖你認得 N / M」（M = 可出題數，由資料算）、還不熟清單（「錯 N 次」，錯最多的在前）、還沒遇到清單、已認識清單、「開始」
- 進度在瀏覽器裡才知道：**靜態 HTML 不得先印出一個假的「0 / 13」再跳成真的數字**——那一瞬間的 0 就是進度條在說謊。分子與清單在讀到 localStorage 之後才出現
- 13 / 13 之後照樣可以玩，出題就在已認識的層裡隨機

### 一局的流程

- 開場 → 題目 × 題數 → 結算。一局的進行狀態**只在記憶體裡**：重新整理、離開再回來，都回到開場、重新出題。不跳離開確認
- 每一題上方：題號 / 題數、題目文字（`symbol.name` 原文，含括號）
- **結算畫面**：答對數 / 題數；答錯清單，每列「{題目符號名} · 你答成了{X}」，點下去到 `/symbols/{題目符號}`；更新後的「你認得 N / M」；「再玩一次」（依更新後的進度重新出題）；「回到平面圖」（`/layouts/{id}`）。答錯的符號文案寫「之後會再出現」，不承諾下一局
- 結算文字不誇獎、不責備

### 首次引導

- 與平面圖頁**共用同一句**（兩段式點擊的引導）與同一個 key `fp:hint:tap:v1`：在哪一頁先看到都算看過。找找看頁在第一題的狀態列顯示它

### 移除 `?fitLocked=1`

- 檢視器不再從網址讀視野鎖定。狀態機的 `fitLocked` 與 `SET_FIT_LOCKED` 不動，改由找找看頁在出題期間打開

### 文案與畫面

- 所有新字串進集中管理的文案模組（題目句型、回饋、「你點的是」、「共 N 處」、結算、開場、入口按鈕、中性熱區標籤、頁面標題與描述）
- **畫面照現有檢視器的樣式與設計 token 做，驗收不包含「與設計稿一致」**。`design/Quiz.dc.html`、`Progress.dc.html` 早於 v0.4，只當流程參考（出題 → 放大 → 答對／答錯 → 結算的順序、回饋不用紅綠、進度用刻度不用百分比）；它們的數字、符號、「46 SVG 單位」一律不照抄。設計稿重畫是另一張不擋 M4 的票

## Testing Decisions

**什麼是好的測試**：只測外部行為——使用者打開哪個網址、看到哪些字、點在哪個位置之後圖上哪些熱區是什麼 State、localStorage 裡寫了什麼。不測元件內部 state、不斷言 reducer 回傳的物件形狀。

**兩條 seam，都是既有的：**

**① 頁面層 / 真瀏覽器（既有，主要）**——`playwright.config.ts` 的 `webServer` 跑 build 產物。找找看的所有使用者可見行為走這條。題目是隨機的，測試用兩個手法變成確定性的：

- **找答案**：讀畫面上的題目文字（＝`symbol.name`），用資料檔對回 symbol id，再從 floorplan 資料找出它的熱區——想答對就點其中一個，想答錯就點另一個符號的熱區。沿用既有的兩段式點擊 helper
- **決定出哪幾題**：用 `page.addInitScript` 在頁面載入前塞好 `fp:progress:v1`（prior art：`tests/affordance-hint.spec.ts`），讓優先序剛好切在題數上。**只在 key 不存在時寫入**：`addInitScript` 每次導航都會重跑，無條件寫入的話，重新整理那一下會把 app 剛寫進去的紀錄蓋掉——案例 20 就會測到假的結果。例：6 個還沒遇到 + 3 個還不熟（錯 3、2、1）+ 4 個已認識 → 這一局的集合必定是那 6 個加上錯 3 次的那一個。**只斷言集合，不斷言順序**

**③ 純函式 / node context（既有，只用在出題）**——prior art：`tests/search-matching.spec.ts`，不需要 `page` fixture，不新增框架、不改 config。範圍**只限「一局出哪些題、幾題」這一個函式**。理由與 M3 開這個例外時相同：真資料只有一種形狀（13 個可出題符號），而會出錯的正是它做不出來的形狀——可出題數為偶數、為 0、某一層的數量少於剩下的空位。這些在 ① 要測就得改資料重跑 `next build`，不屬於任何一條 seam。餵**手寫的小輸入**與固定的亂數序列，不讀真資料。

**② build 時資料驗證**這次不用：M4 沒有新增資料檢查（`quiz_enabled` 在驗證器與程式裡本來就沒有人用）。

**既有測試要跟著動的**：

- `tests/pan-zoom.spec.ts` 裡「fitLocked 擋得住使用者發起的縮放，擋不住第一段的自動放大」搬到 `/layouts/3b2l_standard/quiz`，按「開始」之後照原本的步驟驗
- 同檔「展開說明卡後直接點圖上另一個符號」的「鎖定視野」變體**刪除**：找找看裡說明卡只在作答後打開（作答前唯一會開卡的路就是選定熱區，那一下就是作答），作答後圖暫停，而「下一題」會收起說明卡——三件事合起來，那個情境不會發生。**刪除的前提是案例 14 驗到「下一題」收起了展開的卡**。「一般模式」變體保留
- **`tests/sitemap.spec.ts` 會紅，必須改**：「列的每一頁都真的產出了，產出的每一頁都列在上面」拿 `out/` 遞迴掃到的內容頁與 sitemap 比對，找找看頁會被掃到、卻刻意不在 sitemap 上。改成比對時排除帶 `noindex` 的頁——排除條件看頁面自己的宣告，不另列一份「哪些路徑不算」的名單

**必須涵蓋的案例**：

1. `/layouts/3b2l_standard/quiz` 回 200，HTML 帶 `noindex`，標題不等於平面圖頁的標題
2. sitemap 仍然是 19 個網址，不含找找看頁；sitemap 測試的「產出的每一頁都列在上面」排除 `noindex` 頁之後照樣成立
3. 平面圖頁與首頁各有一個連往找找看的入口；符號頁沒有；平面圖頁加了入口之後檢視器的框高度不變（375 × 812）
4. 開場畫面：預先塞好的進度 → 「你認得 N / 13」與還不熟（依錯誤次數排序、寫出次數）／還沒遇到清單正確；空 localStorage → 0 / 13、13 個都在還沒遇到
5. 題數：主圖一局 7 題，題號 / 題數正確顯示
6. 出題優先序（① 的確定性手法）：6/3/4 那組進度 → 這局集合正確
7. 出題期間雙指縮放、拖曳、雙擊放大都被擋；第一段的自動 3× 照常
8. 第一段圈出候選、「重選」、第二段沒點中：都不前進到回饋、localStorage 不變
9. 答對（點題目符號的任一處）：被點中的是 `selected`，其餘各處是 `revealed`；說明卡沒有自動打開；`correct[題目]` +1
10. 答錯：題目符號每一處是 `revealed`，被點中的是 `selected`；說明卡自動打開且顯示題目符號；卡上有「你點的是 X」；`wrong[題目]` +1、`wrong[X]` 不變；有 `revealed` 熱區的房間沒有被壓暗
11. 答錯且 X 在題目的 `confused_with` 裡（例：題目柱、點牆）→ 卡上有那一筆 `difference` 原文；X 不在裡面（例：題目窗、點柱）→ 沒有差異句
12. 找找看的說明卡有「共 N 處」、沒有「目前第 M 處」與「看它在圖上的其他位置」
13. 作答後：點圖、雙擊、鍵盤 Enter／空白鍵都不改變任何熱區的 State；關閉說明卡後 `revealed` 與 `selected` 都還在
14. 「下一題」：標記清掉、題號前進、視野回到全圖；說明卡在展開狀態下按「下一題」也會收起
15. 作答前，每一個熱區的替代文字都不含任何符號名字；狀態列在第一段之後不含符號名字；沒有任何熱區是 `revealed`
16. 作答後，只有 `selected` 與 `revealed` 的熱區替代文字含名字，其餘仍是中性標籤
17. 鍵盤：Tab 到一個熱區、Enter 或空白鍵作答，判定與手指路徑相同
18. `/layouts/3b2l_standard/quiz?symbol=window` 不高亮任何熱區
19. 結算畫面：答對數正確；答錯清單每列有「你答成了 X」且連到 `/symbols/{題目}`；「你認得」的數字已更新；「再玩一次」回到第 1 題；「回到平面圖」到 `/layouts/3b2l_standard`
20. 答到第 3 題時重新整理 → 回到開場；前 2 題的紀錄已經在 localStorage（預塞進度用「key 不存在才寫」，見上）
21. localStorage 被封鎖：開場、作答、結算都能走完，不丟例外（沿用 `affordance-hint.spec.ts` 封鎖 localStorage 的寫法）
22. `version` 不符的進度紀錄 → 視為空紀錄，第一次作答後寫回 `version: 1`
23. 首次引導：在平面圖頁看過之後進找找看不再出現；清空 localStorage 直接進找找看會出現
24. 平面圖頁加 `?fitLocked=1` 不再鎖住視野（雙指縮放照常）
25. （③）題數：可出題數 13 → 7、12 → 6、1 → 1、0 → 0
26. （③）優先序：還沒遇到先於還不熟先於已認識；還不熟依錯誤次數由多到少；某一層不夠時由下一層補；輸出沒有重複
27. （③）紀錄裡有不在可出題符號裡的 id → 被忽略，不會出成題目
28. （③）固定亂數序列下輸出穩定；不同序列只改變順序與同層內的挑選，不改變層的優先

## Out of Scope

- **房間變暗、依類別重新著色**：PRD 從來沒有這個需求（ADR-0005 2026-09-14 補註）。說明卡開著時的房間變暗是 M2 已上線的功能，不動
- **`discovered`**（自由看圖時標出已認識的符號）：決議不做，會干擾辨識線條（PRD §6.1.2）
- **「只考門窗」這類依類別或房間出題**
- **「只練還不熟的」特別局**：出題優先序已經涵蓋
- **排行榜、分享成績、帳號、跨裝置同步**（PRD §6.3）
- **獨立的學習進度頁**：進度住在找找看的開場與結算畫面
- **續玩一局、離開確認視窗**
- **Analytics 埋點**，包括 §6.3.2 的「記錄實際點了哪一個 `hotspot_id`」與 §9.1 的 `symbol_view { source: "quiz" }`：M5
- **設計稿重畫**：另開票，不擋 M4
- **讓完全看不見畫面的讀螢幕使用者能有意義地遊玩**：題目考的是辨認圖形，這是題型本質（PRD §9 v0.7）。鍵盤路徑服務的是看得見、用鍵盤操作的人
- **補登鄰近配對的 `confused_with`**（例如柱↔窗）：位置相鄰不是畫法相似（PRD §6.3.3）

## Further Notes

- **這是同一種病的第四次。** v0.5 寫「6 題，兩局剛好覆蓋全部 13 個」，6 × 2 = 12。前三次是 M2 的 44px、M3 的轉載與 `caution`。題數公式 ⌈N ÷ 2⌉ 讓「打完兩局必定覆蓋」對任何 N 都成立，而 ③ 的案例 25 就是把這條算術釘住的地方。前提是兩局都打完、進度記得住；中途離開的那一局沒答到的題，下一局仍在「還沒遇到」那一層優先出。
- **「重選逛圖」是已知、接受的漏洞**：反覆「點一下拿到 3× → 重選」可以把整張圖看一遍，繞過視野鎖定。沒有排行榜、成績不跟別人比，而逛圖就是在看符號。不要為它寫防護。
- **作答後暫停的形狀交給 `/codebase-design`**，而 ADR-0006 的推翻條件正好寫到它：「高亮期間需要一套 browsing 沒有的行為——那時它才真的是一個階段」。那份設計若決定新增 stage 或外包一層，都值得寫 ADR（難逆、會被問、有具體被拒絕的替代方案）。說明卡「由外部指定顯示哪個符號」也在同一次設計裡定。
- **`revealed` 的 `data-state` 要與 `highlighted` 看起來不同**。兩者形狀一樣，視覺上分不出來的話，從符號頁帶著 `?symbol=` 進平面圖的人會以為自己在答題（反之亦然）。找找看頁本身不掛高亮，所以兩者不會同時出現在一頁上，但使用者會在兩頁之間移動。
- **`FloorPlanRenderer` 裡 `RoomState` 的註解**寫著「`muted` 是目前唯一的一種：M4 找找看要把某個房間整個變暗」——M4 決議不做，碰到那個檔案時順手改掉那半句。
- **圖上最容易點錯的應該是柱與相鄰的窗**：4 對實際重疊的熱區全是這一組（PRD §6.1.1），而它們沒有 `confused_with`。答錯時那一句「你點的是柱」沒有差異句是正確行為，不是缺資料——點歪與看錯是兩件事，差異句只治看錯。
- **題目用 `symbol.name` 原文**，「出入口（無門扇）」的括號描述的是意思（這裡沒有門），不是畫法（牆斷開、一個小三角），不構成洩題。另寫一份「題目用名稱」就是題庫，PRD §6.3 明講不建。
