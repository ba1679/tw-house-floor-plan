# 08: 展開說明卡後重新選取，保留點擊目標的位置

**Status:** ready-for-agent
**Priority:** P1
**Type:** bug
**Related:** 03（說明卡）、04（pan/zoom）
**Review baseline:** `b5015cc`，2026-09-08

## 問題與影響

說明卡展開後直接點圖，點到的 hotspot 雖然進入候選，卻可能被移出可視區域。
一般模式必須額外拖曳才能找回；`fitLocked=1` 同時禁止平移與縮放，使用者無法完成這次選取。
這違反 spec user story 10「不必先重選就能看下一個」與兩段式可選到符號的要求。

## 重現步驟

1. 使用 375×812 CSS px viewport，開啟 `/layouts/3b2l_standard?fitLocked=1`。
2. 以兩段式選到主臥雨遮 `hs-canopy-master`。
3. 點「上拉看完整內容」，等卡片展開及圖面縮小完成。
4. 不關閉卡片，直接點縮小圖面中左下角柱 `hs-col-sw` 的中心。
5. 等卡片收合與圖面放大完成，檢查柱的位置與可選取性。

Review 實測：柱成為 `candidate`，但 bounding box 約為 x = −237px、width = 43px；
viewport 的水平範圍是 16–359px，因此柱完全在畫面外。未鎖定模式也有目標移出畫面的問題。
數字是診斷紀錄，不要把它們寫成測試的固定預期值。

## 成因與修正方向

`lib/viewer/interaction.ts` 的 `firstTap` 先用卡片尚未收合的框呼叫 `clampView`。
展開時 fit 很小，`fit × 3` 仍可能小於 1，水平中心因此被夾回圖面中央，丟失原本的點擊位置。
後續 `RESIZE` 雖把倍率調回 3×，卻無法恢復被夾掉的中心。

修正應保留原始點擊目標，依收合後的框完成候選視野定位；具體實作由修票者決定。
不可改回絕對 3×：那會重新引入卡片收合後約 14.4× 的舊問題。
參照 `docs/adr/0004-auto-zoom-never-shrinks-the-users-view.md`，仍須保留使用者已設定的較高倍率。

## 驗收條件

- [ ] 上述流程中，目標柱在卡片收合後仍有可點擊的可見區域，第二段可實際選中並開啟柱的說明卡。
- [ ] 一般模式與 `fitLocked=1` 都能完成，不需先關卡、重選或手動平移。
- [ ] 涵蓋圖面邊緣目標及展開卡片後連續選取，不能只斷言 `candidate` 或「再點一次確認」提示出現。
- [ ] 不回歸絕對倍率過度放大；使用者已放大到 4× 時不被自動縮回 3×。
- [ ] 既有說明卡、兩段式、pan/zoom 測試通過。
