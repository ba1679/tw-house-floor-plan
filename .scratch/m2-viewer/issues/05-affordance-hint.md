# 05: 可點擊性提示

**What to build:** 第一次進站的使用者知道這張圖是可以點的，而不是把它當成一張靜態圖片直接離開。這是檢視器的核心 UX 問題——若整張圖都是熱區但毫無提示，使用者會直接放棄（PRD §6.1.2）。

**Blocked by:** 02（兩段式點擊選到符號）

**Status:** done

- [x] 首次進入顯示極輕量的一次性引導，文案對上兩段式操作：**「點圖上任何一個位置，我們會放大讓你看清楚」**——不是舊版的「點擊圖上的標記」。使用者不需要精準點到標記，這正是兩段式要傳達的事
- [x] 引導出現一次後以 localStorage 記住，回訪不再顯示
- [x] 熱區有**非常克制的**視覺提示（微弱底色或極慢脈動）
- [x] **不得持續閃爍**——這張圖本身是學習對象，干擾性動效會破壞辨識
- [x] 桌機提供 hover 狀態；手機無 hover，因此靜態提示必須自身足夠明確
- [x] 測試涵蓋：首次載入出現引導；清掉 localStorage 後再現；第二次載入不出現

### `/code-review` 之後改的東西（2026-09-10）

兩軸各抓到真的東西。

**1. 6% 的底色在小熱區上等於沒有。** 底色的可見度跟面積成正比，而這張圖要教的符號正好都很小——
375px 全圖下量到的短邊：客廳窗 6.9px、大門 6.9px、柱 11.5px。6% 的藍疊在白底上是
rgb(240,247,251)、對比 1.08:1，鋪在一條 6.9px 的細長條上看不出來。而「手機無 hover，
因此靜態提示必須自身足夠明確」時，回訪的手機使用者**只剩下這一層**。
改成底色 10% ＋ 一條 0.5 alpha 的細邊：細邊不吃面積，`non-scaling-stroke` 讓它在任何倍率、
任何大小的熱區上都是 1px。仍然沒有動畫。

這是兩條要求對撞之後的取捨：「非常克制」與「足夠明確」在 6.9px 的熱區上不可能同時最大化。
判準取後者，因為前者還有一道保險——進入候選或說明卡階段這一層就整個收起來，
使用者真正在讀一個符號的時候，圖上是乾淨的。

**2.「不得持續閃爍」那條測試永遠會過。** 它量的是群組 `<g>`，而提示的每一條規則都掛在
`.hotspots rect`——量一個沒有人設過動畫的元素，`animation: blink 1s infinite` 加在 rect 上
也照樣綠。改成量 rect，而且量最小的柱。

**3. `pointer-events` 從 `none` 放寬成 `auto`，範圍比需要的大，還把原本的理由刪掉了。**
需要 hover 的只有有精準游標的機器、只有畫得出提示的那幾個狀態，所以放寬收進
`@media (hover: hover) and (pointer: fine)`，而且只給真的有 hover 規則的選擇器。
原本那句「點擊收在可視區域上：兩段式點的是圖上一個位置，不是這個熱區」寫回去了，
後面補上為什麼放寬不會動到判定：命中是 `distCm` 算出來的，不是靠事件打在哪個元素上。

**4. `id="hotspots"` 跟產生器自己那組熱區同名。** `lib/floorplan/artwork.ts` 讀圖時把產生器
那個 `<g id="hotspots">` 剝掉，而它自己的註解已經寫下風險：產生器改個名字，剝除就會靜靜地失效。
在票 05 之前那只是多一個沒人選的 id；票 05 之後 CSS 與全部測試都靠 `#hotspots` 定址，
就會選到錯的那一個，而畫面上看不出來。改名 `hotspot-layer`。

**5. 第二段沒有 hover。** 桌機使用者最壞要在 9 個重疊的候選裡挑一個，而 hover 規則被
`data-stage="browsing"` 一起擋掉了。補了 `rect[data-state="candidate"]:hover` 與一條測試。

另外照標準軸的意見：測試不再拿 `data-hint` 當斷言（它是元件 state 的投影，
spec §Testing Decisions 說不斷言這種東西），只留它當 hydration 的閘門；`onPointerDown` 的
`useCallback` 改成相依 callback 本身（`useViewerGestures` 每次 render 都回傳新物件，
原本那組相依等於沒有 memo），覆寫也收進同一個 props 物件，不再靠 JSX 屬性的先後順序。

修測試時另外撞到一個：`fill: transparent` 的 computed 值是 `rgba(0, 0, 0, 0)`，
而 `stroke: none` 是 `none`。只比對其中一種，另一種會安靜地通過——「沒有細邊」一度被判成
「有細邊」。改成一個 `painted()` 判斷，兩種都認。

驗證：`npm run typecheck` 通過；`npx playwright test` 對 SSG 產物全套 50 條通過。
375×812 實機視覺確認：小符號（窗、門、柱、管道間）現在各自框得出來，圖面線條、房名與尺寸
仍然清楚。
