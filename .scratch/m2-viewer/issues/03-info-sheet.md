# 03: 說明卡 bottom sheet

**What to build:** 使用者確認符號後，說明卡從螢幕底部升起，告訴他這是什麼、要注意什麼，**以及這個說法是從哪份文件來的**。卡片永遠不佔滿螢幕——上緣留給平面圖，使用者才不會失去「我剛剛點的是哪裡」。

來源徽章是這個產品相對於一般房產內容網站的核心差異化：不只給答案，而是給答案的出處與可信度（PRD §6.5）。

**Blocked by:** 02（兩段式點擊選到符號）

**Status:** ready-for-agent

- [ ] 欄位順序：符號名稱 → 分類 → 來源徽章 → 白話意思 → 注意事項 → 「這張圖上共 N 處 · 目前第 M 處」→ 免責聲明
- [ ] 兩段高度：初始 392px（46%）、展開 660px（78%）。展開上限的依據是「平面圖僅餘 84px」——足夠維持位置感，不足以繼續操作
- [ ] 初始高度下注意事項必然被截斷 → 需要漸層與「上拉看完整內容」提示
- [ ] 卡片內容**全部取自 symbol 資料**，一字不在元件裡寫死
- [ ] 來源徽章依 `source_tier` 四種呈現（`cns` / `regulation` / `convention` / `varies`，文案見 PRD §6.5）
- [ ] **`source_tier` 與 `verification_status` 是兩條不同的軸**，不可互相取代或合併顯示（`CONTEXT.md`）。`verification_status` 不上前台
- [ ] 「共 N 處」由 `floorplan.hotspots` 依 `symbol_id` 統計得出，**不得寫死**；`symbol_id` 為 `null` 者不計入
- [ ] 免責聲明固定在卡片最底，不隨捲動消失
- [ ] 關閉鍵與「看它在圖上的其他位置」列量得出 **≥ 44×44 CSS px**（這是 M2 完成定義裡 44px 那一條真正指涉的東西）
- [ ] 卡片開啟時平面圖仍可見且維持選中標示
- [ ] 桌機有 hover 狀態；**不用 hover tooltip 承載說明內容**（手機沒有 hover）
- [ ] 測試涵蓋：選到符號後卡片出現且含該符號的白話意思；控制元件量得出 ≥44px；「共 N 處」與資料一致（窗 9 處、單扇門 5 處、柱 5 處）

> `design/Main.dc.html` 是 v0.3 時期的稿：示範用的「密閉式撒水頭」在 v0.4 砍設備類符號時已不在 14 個之內。**版面尺寸（392/660px、84px 下限、44px 命中）是實測出來的，照用；內容欄位換成實際存在的符號。**
