# 02: 符號頁——這是什麼

**What to build:** 有人在 Google 打「平面圖上的虛線是什麼」，點進搜尋結果，落在一頁自己站得住的內容上：這個符號叫什麼、畫出來長什麼樣、白話是什麼意思、容易跟什麼搞混、買房時要注意什麼。他不必先看首頁，也不必往上找導覽。

**Blocked by:** None (can start immediately)

**Status:** done

規格：`.scratch/m3-symbol-pages/spec.md` 的「符號頁」「資料投影」。

## 注意

**標題不是把 `name` 直接印出來。** PRD §6.2.1 要求標題對應搜尋意圖——「平面圖上的樑是什麼？」而不是「樑」。標題由 symbol 資料生成。

**「容易搞混」排在「注意事項」之前。** `confused_with` 是這批內容裡最貼近搜尋意圖的東西（「柱跟牆怎麼分」正是人們會打的字），而 `caution` 14 筆裡只有雨遮有——照 PRD 的欄位順序排會把最有價值的東西埋在一個大多數頁面都空著的區塊後面。

**符號圖形取自 sprite，不要另外畫一套。** 本站的核心承諾是「符號頁認得的形狀，回到平面圖上找得到」（PRD §12），而 ADR-0005 之後主圖由檢視器自己畫、且它站 sprite 那一邊。用 sprite 就自動一致。

**投影要分開。** 檢視器說明卡現有的那份投影刻意只挑前台要的欄位，因為它會被序列化進靜態 HTML 當 props。符號頁需要多幾個欄位，但**不能直接加進那一份**——那會讓每一張平面圖頁都夾帶 14 筆查證資料出貨。符號頁是 server component，直接渲染成 HTML，全帶沒有成本。

- [x] 14 個 symbol id 各有一張 `/symbols/<id>`，全部回 200
- [x] 標題對應搜尋意圖，14 頁彼此不同，且都不等於根版面的標題
- [x] 每頁有自己的 meta description
- [x] 顯示大尺寸來源徽章，四種 `source_tier` 各自的文案正確
- [x] 顯示符號圖形，取自 sprite
- [x] 顯示白話意思
- [x] 顯示「容易搞混」，每一則都連得到對方的符號頁
- [x] `caution` 為 `null` 時整區不出現——不留標題、不留空白（13/14 是這種）；雨遮那頁有
- [x] 頁面上的字與資料檔**一字不差**：測試自己讀符號資料比對，**不要**用「改一筆資料看頁面跟不跟著變」來測（那需要重跑建置，不屬於任何一條 seam）
- [x] `verification_status` 的四個值都不出現在任何一頁的 HTML 裡
- [x] 平面圖頁的產物**沒有**因此夾帶查證欄位
- [x] 資料驗證加一條：每個符號的必填內容欄位非空（名稱、白話意思、`svg_ref`、分類、`source_tier`）
- [x] 符號圖形有替代文字；Tab 走得完頁面上所有可操作的東西
- [x] 375px 手機寬度下不溢出、不橫向捲動

## Comments

**2026-09-12 — 做完了。**全套 **90** 條綠（既有 70 + 符號頁 14 + 建置驗證 6）、`npm run typecheck`
乾淨、真資料 `npm run validate` 0 errors／1 warning（樑那條預期中的）。真資料一個字都沒動。

14 張 `/symbols/<id>`，欄位順序：標題 → 大尺寸來源徽章 → 符號圖形 → 白話意思 → 容易搞混 → 注意事項。
**順序照 spec，不照設計稿**——稿子把徽章排在末段、也沒有「容易搞混」，那份稿在這一點上已被
2026-09-12 的決議推翻。這件事寫進 `page.module.css` 的檔頭，否則下一個拿稿子對照的人會以為做錯了。

**投影分成兩個函式，名字各自說出自己的消費者。**`loadSymbols()` 改名 `loadSymbolsForViewer()`，
新增 `loadSymbolsForPages()`（＝說明卡那一份再加 `svg_ref`）。改名不是順手整理：這個模組從今天起
有兩份形狀，而 `loadSymbols()` 這個名字答不出「哪一份」——而答不出來的那一天，就會有人把
`source_refs` 加進會被序列化進每一張平面圖頁的那一份。讀檔的私有函式叫 `readSymbolFile()`，
註解寫明它回傳的是**含查證欄位的整筆**、所以不匯出。

**符號圖形內嵌 sprite 的那一段 SVG，不用 `<use href="sprite.svg#id">`**：外部 `<use>` 在
Chrome／Safari 不會載入，後果是靜默留白——在一張 SEO 落地頁上看起來像設計沒做完。
測試逐字比對 sprite 的原始碼，所以「另外畫一套」的那一天它會紅。

**替代文字取自資料的 `name`（`「牆」在平面圖上的畫法`），不是 sprite 自己的 `<title>`。**
兩者目前 14 筆全部相同，但那是巧合不是保證：名字是內容，改資料就該全站跟著改。

**大尺寸徽章獨立成 `SourceTierPanel`，圖標抽成 `SourceTierIcon` 給大小兩版共用。**
四段 `explainer` 逐字取自 `design/Badges.dc.html`。**沒有印稿子上那行 `SOURCE_TIER: CONVENTION`**
——那是給看稿的人對照 enum 用的，首購族看到一串英文常數不會多懂什麼。
`SHEET_SECTIONS` 改名 `SECTION_LABELS`：同一個區塊在說明卡與符號頁必須同名，
順序可以不同（而且刻意不同）。

**測試的形狀**：14 條裡 9 條讀 `out/` 的建置產物而不是開瀏覽器——要驗的正是
「內容在 HTML 裡就有，不必執行 JavaScript」，而那件事只有拿靜態檔案本身來問才問得到；
要量 375px、走 Tab、點連結的才進瀏覽器。全部比對的是**資料檔裡那一字不差的字串**，
沒有用「改一筆資料看頁面跟不跟著變」（那需要重跑 `next build`，不屬於任何一條 seam）。

驗證器新增 `REQUIRED_CONTENT`（`name`／`plain_meaning`／`svg_ref`／`category`／`source_tier`），
沿用 `REQUIRED_WHEN_VERIFIED` 的寫法：**欄位與它的理由同一行**，錯誤訊息說得出少了它那一頁會缺什麼。
原本單獨那條 `缺 svg_ref` 併進來（同一件事不留兩處訊息）；`category` 的 enum 檢查改用 `.get()`，
否則欄位不見時是 `KeyError` 炸在驗證器裡，而不是一條說得清楚的驗證錯誤。
**在 sandbox 裡反向驗過**：把 `REQUIRED_CONTENT` 那一輪拿掉、資料清空一個欄位，退出碼回到 0——
確認這 6 條測試真的在守東西。

`CONTEXT.md` 新增「**符號圖形（Symbol Art）**」一條，並在「圖面（Artwork）」的 `_Avoid_` 補上
反向指引。理由是這次真的長出一個新概念：一個符號畫出來的樣子，與「一整張 floorplan 畫出來的樣子」
是兩件事，而兩者的英文都會想叫 art。沒寫 ADR——內嵌 sprite 是可逆的渲染選擇，
理由留在 `lib/symbols/sprite.ts` 的檔頭就夠。

`spriteArt()` **刻意不快取**：sprite 不是模組，`next dev` 不會因為它變了而重新求值，
模組層快取會一路撐到重啟。與 `data.ts` 每次重讀同一條規矩。

### 留給後面幾張票的兩件事（不在這張票的範圍）

- **`varies` 這一級的文案沒有被真資料走過**：14 筆只有 `cns`／`regulation`／`convention`。
  第四種由 `SOURCE_TIER_BADGES` 的 `Record<SourceTier, …>` 型別擋住（少一個 key 直接編譯失敗），
  但沒有任何一頁證明它渲染得出來。M1 若哪天把某個符號改成 `varies`，那一頁就是第一個實例。
- **符號頁與說明卡的 CSS 有一組同名 class**（`.section`／`.prose`／`.confusedList`⋯），
  值刻意不同。這次不抽共用：抽了會逼兩邊共用尺寸，而尺寸正是它們唯一該分開的東西
  （說明卡壓在 46vh 裡站著掃，符號頁是坐著讀的）。理由寫在 `page.module.css`。
