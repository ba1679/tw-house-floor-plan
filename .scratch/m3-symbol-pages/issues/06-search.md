# 06: 搜尋

**What to build:** 想查特定符號的人不必在三張分類頁裡翻——打幾個字，結果當場出現。他打的是俗稱也找得到：打「灑水頭」不必知道正式名稱，打「暗樑」找得到「樑」。

**Blocked by:** 05（搜尋框要有地方放，結果要有地方連）

**Status:** done

規格：`.scratch/m3-symbol-pages/spec.md` 的「搜尋」與 Testing Decisions 的第三條 seam。

## 注意

**不開 `/search` 路由。** 全站是靜態輸出，產不出搜尋結果頁的 HTML——那一頁對搜尋引擎是空殼，卻仍然會被收錄。搜尋是頁面上的一個元件，不是一個網址。

**索引在建置時內嵌，不 fetch、不打 API。** 14 個符號 × `id`/`name`/`aliases`/`category` 大約 2KB，比一張小圖還小。

**比對邏輯是純函式，與 UI 分開。** M4 的找找看要從同一份索引出題，分開才不必重寫。

**正規化只做三件事：大小寫、前後空白、全形轉半形。不做簡繁轉換**——受眾是台灣人（PRD §3），加一張對照表要維護，而且會讓比對結果變得難以預測。

## 這張票帶一條新 seam

M2 立過一條規矩：不另外替純模組開單元測試。那條規矩的理由很具體——已知的 bug 都躲在螢幕像素與圖面公分的換算層，只測純模組會把最會壞的地方留在測試外。

**這條理由在搜尋上不成立**：比對邏輯與版面尺寸完全無關，而它的風險是**組合性的**（46 個 aliases × 大小寫 × 全形半形 × 空白），瀏覽器測試只能抽樣，抽不到的那一組就是會出事的那一組。

所以這張票刻意破例開一組單元測試。它跑在既有測試框架的 node context 裡，**不新增測試框架、不改設定**——seam 多了一個入口，工具鏈沒有變。

- [x] 分類頁上有搜尋框，打字當場出結果：不換頁、不 fetch、不需要按送出
- [x] 比對涵蓋 `name` 與 `aliases`，子字串命中即可
- [x] 大小寫、前後空白、全形半形都不影響結果（單元測試）
- [x] 打「暗樑」找得到「樑」；打 `beam` 也找得到（單元測試）
- [x] 沒有命中時給得出「找不到」的回饋，不是一片空白
- [x] 比對邏輯是不碰 DOM 的純函式，與搜尋元件分開
- [x] 內嵌的索引只含 `id` / `name` / `aliases` / `category`——不夾帶查證欄位
- [x] 結果連得到符號頁
- [x] 鍵盤可操作：Tab 進得了搜尋框，結果列表走得完

### 票面以外多做的四件事，各有一條測試

- **排序分兩組：名字對上的在前，只有別名對上的在後，組內照資料檔。**不分的話，打「樑」會先列出柱——
  柱的別名「樑柱」含這個字，而柱在資料檔裡排在樑前面。沒有另外發明權重。
- **結果列說得出為什麼是它。**只有別名對上時印「又稱「流理台」」（資料裡的原文，打 `ps` 印的是「PS」），
  另外印它屬於哪一類——結果是三類混在一起的，索引帶著 `category` 就是為了這個。
- **注音組字到一半不比對。**受眾打中文多半用注音，組字中框裡是「ㄢˋ」；那時候就比對，狀態列會說
  「找不到符合『ㄢˋ』的符號」，每一次搜尋的第一個鍵都被回絕一次。框裡的字與拿去比對的字分成兩份，
  `compositionend` 才算打完。測試走 Chromium 的 DevTools Protocol（`Input.imeSetComposition`），
  先在沙盒裡確認過它送出的事件序列與真的輸入法相同。
- **「找不到」放在狀態列（`role="status"`），有命中時也說幾個。**讀螢幕的人不必把焦點移開輸入框就聽得到。
  狀態列一直在 DOM 裡、空的時候不佔位置——**不能寫成 `:empty { display: none }`**，那會把 live region
  從無障礙樹裡拿掉，第一句話跟著 region 一起冒出來，不少讀螢幕軟體不唸。

### 小決定

- 正規化**不用 `normalize("NFKC")`**，只轉全形 ASCII 那一段（U+FF01–FF5E）與全形空白。NFKC 會多做很多事
  （相容漢字併進正規漢字、「㎡」拆成「m2」），正是票面要避開的「難以預測」。資料那一側也過一次：
  「出入口（無門扇）」的括號是全形，打半形括號要找得到。
- 什麼都沒打、或只打空白，一個都不列：空字串是每一串字的子字串，不擋的話按一下空白鍵就列出 14 個。
- 結果連結 `prefetch={false}`：結果隨每一個字換一批，預設的預抓會讓打字一路打網路。
  「打字時沒有任何網路請求」有測試釘著。
- 搜尋框排在分類頁內容**之前**，標籤寫「搜尋全部 14 個符號」（N 由索引算）：夾在「結構」的標題底下，
  讀者會以為它只搜結構。
- 375px 那條測試抓到一個真的溢出：「找不到」會把讀者打的字原封不動複述回去，一長串沒有空白的英數字
  沒有斷點。狀態列加了 `overflow-wrap: anywhere`。
- **沒做**：狀態列的 debounce（無障礙指引建議替「打字時一直變的 live region」做，但注音是一個詞一個詞送出的，
  更新頻率本來就低，先不加）；首頁的搜尋框（票 07，同一個元件）。

### 與票面、spec 對不上的一處：「灑水頭」

票面的 What to build、spec user story 21 與 Testing Decisions 第 11 條都拿「灑水頭」當例子，但**資料裡沒有
撒水頭這個符號**——它是設備類，v0.4 砍出範圍（PRD §4.1），14 個符號的 46 個別名裡也沒有「灑水頭」。
字面照做的話那條測試寫不出來。測試改用資料裡真的有的俗稱：「暗樑」「beam」「流理台」「PS」，
另外一條把 14 個名字與 46 個別名 × 七種打法整批掃過。**票面與 spec 沒有改**，例子要換成哪一個留給規格的主人決定。
