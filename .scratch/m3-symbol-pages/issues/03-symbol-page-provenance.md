# 03: 符號頁——從哪來

**What to build:** 讀完符號頁的人往下看，知道這個說法出自哪份文件的哪一頁、是哪一年的版本；如果這份標準是轉載來的，頁面直說「我們沒核對原文」。他因此可以自己判斷要不要信，而不是被要求相信。

**Blocked by:** 02（出處印在符號頁上）

**Status:** done

規格：`.scratch/m3-symbol-pages/spec.md` 的「符號頁」出處段落。

## 為什麼這張值得獨立

這是本站相對於一般房產內容網站的**核心差異化**（PRD §6.5）：不只告訴使用者答案，而是告訴他這個答案從哪裡來、可信到什麼程度。既有的來源徽章元件在註解裡已經寫明「完整出處與可點連結是符號頁的事」——這張票是去兌現那句話。

它也順便解決一件事：M2 決議 `verification_status` 不上前台，所以讀者看不到「這個符號只有 1 筆來源」。把出處清單完整印出來，讀者**自己數得出來**——那比顯示一個內部狀態欄位更誠實。

## 注意

**`url` 缺席要是安全的。** 現況 15 筆 `source_refs` **沒有任何一筆有 `url`**，所以這張票落地時全部會是純文字。缺的那兩筆（雨遮的地籍測量實施規則、建築技術規則）屬於 M1，已另外開票。**不要等它**——渲染端對 `url` 缺席安全，M1 補上之後連結自己長出來，不必回頭改元件。連結那條路用 fixture 驗。

**公會規範永遠不連、也不 host。** repo 根目錄那份 `平面圖符號.pdf` 是別人的著作，不進 `public/`。會有 `url` 的只有法規類。

**`clause` 是定位資訊不是內容轉錄。** PRD §7.1 的著作權紀律在這裡仍然有效：說明文字一律自行白話重寫，符號 SVG 一律自行重繪，引用只標示出處。

- [x] 每一筆 `source_refs` 印出文件名 + 條次／頁碼 + 年份（有的話）
- [x] 四個 `cns` 符號看得到 `via` 那一整行（「轉載自⋯，未核對標準原文」）
- [x] 有 `url` 的渲染成連結，沒有的印純文字——**不因為缺連結而少印一筆來源**
- [x] 連結渲染那條路有測試，用 fixture 驗，不依賴真資料裡有沒有 `url`
- [x] 公會規範那幾筆不出現連結
- [x] 補第 2 筆 `source_refs` 之後頁面自動多一行，不必回頭改元件（用 fixture 驗）
- [x] 雨遮那頁印得出兩筆來源

## Comments

出處是一個獨立區塊，排在注意事項之後（spec 欄位順序第 7 項）。
`design/SymbolPage.dc.html` 與 **PRD §7.2.2 都把 `via` 畫在大尺寸徽章框內**，
2026-09-12 的欄位順序決議把它移出來了，但兩處的字面沒有跟著改。以 spec 為準：
徽章回答「硬到什麼程度」、出處回答「憑什麼」，後者是讀完全文才要的東西。
`components/SourceTierPanel.tsx` 裡那句指向這張票的註解一併改成指得準的說法。

### 一筆出處印成什麼，是一個純函式的事

`lib/symbols/source-refs.ts` 的 `printedSourceRefs()` 決定四件事：文件名、
`clause` + `year` 併成的定位行、轉載那一行、以及連不連得出去。元件只把決定畫出來。

**分開不是分層潔癖，是因為票要求「用 fixture 驗」，而 fixture 進不了三條 seam 裡的任何一條**：
seam ① 讀的是真資料的建置產物，而真資料 15 筆**沒有任何一筆有 `url`**；seam ② 只跑
`validate_data.py`；spec 又明講不要用「改一筆資料看頁面跟不跟著變」來測（那要重跑 `next build`）。
抽成純函式之後 fixture 餵得到它。

**這不是 spec 的 seam ③。** ③ 是為搜尋比對開的，spec 還寫明它是「唯一的新 seam」——
這裡沿用它的形式（純函式、node context、不改 config），破例理由是這張票自己的。
**spec 的 Testing Decisions 那一句因此已經不準**，下一個要開純函式測試的人不必再自證一次。

### 連結那條路真的走過一次

fixture 只證明函式回傳了 `link`，證明不了 JSX 那個分支渲染得出 `<a>`。
落地前**臨時**替雨遮第一筆補了一個 `url`、重跑 `next build`，確認：
連結渲染成 `<a href="https://law.moj.gov.tw/…">看《地籍測量實施規則》原文</a>`，
而第二筆沒有 `url` 的照樣整筆印出。確認後把資料還原（`git status` 乾淨）。
M1 補上 `url` 那天不必回頭改元件。

連結的字帶著文件名（`sourceLinkLabel`）是**自己加的決定**，spec 只說「渲染成連結」。
理由：雨遮那一頁有兩筆來源，兩個連結都叫「看原文」的話，讀螢幕的人分不出哪個通往哪裡。

### 「公會規範不出現連結」守在資料那一端，不是渲染那一端

渲染只看 `url` 在不在。守在資料端的是 `tests/symbol-page.spec.ts` 的
`expect(guild.every((ref) => !ref.url)).toBe(true)`。

**刻意不寫進 `validate_data.py`。** 最自然的寫法會是「只有 `regulation` 類可以有 `url`」
（spec 的字面），但那會擋掉 M1 一個真實的情況：`convention` 符號補的第 2 個交叉來源如果是
《公共工程製圖手冊》這類政府文件，它有全文網址而且該連。用文件名字串去比對又太脆。
所以留在測試裡：它擋得住「公會規範長出 url」這件真正該擋的事，而不會擋到 M1。

### 出處那一區沒有「沒有就不出現」的豁免

`caution` 那一區有（13/14 是空的），出處**沒有**：零筆來源時會留下一個空的「出處」標題。
那正是該讓人看見的——一個說不出自己憑什麼的符號頁是壞的，不該安靜地看起來很正常。
`REQUIRED_CONTENT` 沒有把 `source_refs` 列為必填（spec 的三條新檢查也沒有），
所以這件事由測試顧著：每個符號至少一筆。

`CONTEXT.md` 新增「**出處（`source_refs`）**」一條，並把 Source Tier 那條的
「它描述答案的**出處**」改成「答案**硬到什麼程度**」——同一個詞先前同時指涉兩個概念。

### 留給後面的兩件事（不在這張票的範圍）

- **PRD §7.2.2 寫「沒有 `via` 的 `cns` 一律視為錯誤」，`validate_data.py` 沒有這條檢查。**
  今天 4 個 `cns` 都有 `via`，所以頁面沒有錯；但將來少一個的話，頁面會**靜靜地不印那一行**，
  看起來像我們真的核對過標準原文。這是設備類以外最後一個「靜默少一塊」的缺口。
- **`via` 與 `clause` 的內容重複**：4 筆 `cns` 的 `via` 開頭就把 `clause` 又抄了一次
  （「p32 表 14 坐式馬桶（平面＋立面）」出現兩次）。讀起來囉嗦，但那是資料的事，
  屬於 M1 那兩筆順手修正（`via` 的頁碼應為 p31）的同一批。
