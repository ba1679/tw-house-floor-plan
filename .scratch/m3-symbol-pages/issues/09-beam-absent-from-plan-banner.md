# 09: 樑的「圖上看不到」橫幅

**What to build:** 「樑」的符號頁底部不說「打開三房兩廳，標出這個符號」——那會帶使用者去看一個不存在的東西。它說「**這張三房兩廳上看不到樑——這正是重點 →**」。按下去照樣進平面圖，但圖上跳出一條說明：建案平面圖多半不畫樑，它在施工圖與結構圖上。你看不到它，所以要問。

**Blocked by:** 08（走同一個網址與同一個機制）

**Status:** done

規格：`.scratch/m3-symbol-pages/spec.md` 的「樑（0 個匹配熱區）」。PRD §6.2.1 的例外。

## 為什麼不是把按鈕拿掉

「圖上找不到」本身就是內容。樑在 floorplan 上刻意沒有熱區（PRD §4.2），而那正是這個符號要教的事——轉換率照樣量得到，而且這一頁的說服力更強。

## 注意

**走同一個網址、同一個機制，特例只落在呈現上。** 不要為樑開一條分支路徑：帶 0 個匹配熱區進去是一個合法的狀態，差別只在畫面上顯示什麼。

**不開說明卡。** 兩個理由：使用者剛在符號頁讀完同樣的內容，再推一次是重複；而且說明卡在 M2 是綁著「選中了某個熱區」才開的，沒有熱區硬要開卡會弄髒那條規則。

**票 08 已經定下、會碰到這張票的事**（2026-09-13 規格主人的決定，細節在票 08 的 Comments 與 `docs/adr/0006`）：

- **橫幅的條件可以直接是「高亮了一個符號，但它在圖上對到 0 處」。** `?symbol=` 對不到任何符號（網址打錯）的情況票 08 已經處理：狀態列提示找不到，狀態機不收——`highlightedSymbol` 只會是真的符號（D4）。
- **狀態列與橫幅要對齊。** 對到 N 處時狀態列說「○○在這張圖上共 N 處，都亮起來了。」；對到 0 處時不說這一句，由橫幅接手（D2）。
- **橫幅不能直接掛在 `highlightedSymbol` 上。** 那一欄在使用者圈出候選或按 Enter 時就清掉（D1），而橫幅要留到使用者自己關。

- [x] 樑的符號頁按鈕文案是「這張三房兩廳上看不到樑——這正是重點 →」
- [x] 按下去進到平面圖，**沒有**說明卡跳出來
- [x] 圖面上出現橫幅說明，文案講清楚樑為什麼不在圖上
- [x] 橫幅關得掉；關掉之後圖面的操作完全正常
- [x] 橫幅在的時候 pan / zoom / 兩段式點擊照常
- [x] 其他 13 個符號的行為不受影響（帶有匹配熱區的照樣高亮，不出現橫幅）
- [x] 375px 下橫幅不遮住圖面到無法操作的程度

### 做了什麼

- **符號頁的按鈕只換字。**那個 symbol 在該 layout 上 0 處時，字換成 `absentSymbolButton`（`lib/ui/copy.ts`）：
  「這張三房兩廳上看不到樑——這正是重點」，格局名取 `floorplan.name`、不寫死。網址、畫法、`highlightHref` 都不變。
- **「0 處」只有一個算法。**`lib/floorplan/hotspots.ts` 新增 `hotspotsOfSymbol`，`occurrencesOf` 改成呼叫它；
  符號頁決定按鈕的字、檢視器決定要不要出橫幅，問的都是它——按鈕說看不到，進去就有橫幅，兩邊不會各數各的。
- **橫幅記在檢視器元件自己的 state**（`absentSymbol`，`components/FloorPlanViewer.tsx`）。落地時（`highlightSymbol`）
  數出 0 處才記下，使用者按「知道了」才清。不掛在 `highlightedSymbol` 上（那一欄開始選東西就清，D1），也不進 `ViewerState`：
  狀態機裡沒有任何判斷讀它，它與「找不到網址指定的符號」那一句是同一種東西。ADR-0006 原本「是票 09 的決定」那一段改寫成這個決定。
- **位置：圖的正上方、框的外面。**不疊在圖上——疊上去會蓋掉一塊圖，而且落在手勢的範圍裡，點橫幅會被當成點圖。
- **說明卡升起時讓位，收起來就回來。**375 × 812 量過：橫幅 91px + 12px 間距。全圖時拿走的是留白，框一 px 都沒少；
  但卡片一升起就是從圖上挖——可視帶 334.7px → 231.3px，展開時 187.7px → 84.3px。與頁尾讓位同一個理由（`SiteFooter.module.css`），
  條件與掛上 `<InfoSheet>` 的是同一個。讓位不是關掉。
- **狀態列**：0 處時本來就不說（D2），這張票沒有替它加任何一句。
- **驗證器那條 warning 改寫**：「宣稱在某張圖上、該圖沒有熱區」原本說「只做符號頁」，已經不對了。現在說出按鈕與橫幅會怎樣，
  以及橫幅那句說明是為樑寫的（見下面「留給規格的主人決定」第 1 條）。
- 視覺：左邊一條琥珀色邊，與高亮的邊同色——兩者都是「從符號頁帶進來的那一層」。375px 截圖看過，關閉鍵與控制列的按鈕同一個樣子、44px。

### 測試（7 條）

1. 樑的符號頁：按鈕是那一句，按下去照樣進 `related_layouts` 那張圖
2. 落地：橫幅講得出「看不到樑」與「施工圖與結構圖」；說明卡沒開、什麼都沒亮、狀態列沒說「都亮起來了」
3. 橫幅關得掉；關掉之後兩段式開得出說明卡，收起卡片橫幅也沒有自己回來
4. 橫幅在的時候雙指縮放、拖曳、回到全圖、兩段式照常，而且它一路留著
5. 375px：全圖時框與沒帶符號進來時一樣高、橫幅沒疊到圖上；說明卡升起時它讓位（可視帶與沒帶符號時一樣高），收起來又回來
6. 其餘的符號：落地照樣亮起每一處，不出現橫幅
7. 建置產物：「看不到」那一句只在樑的符號頁上，其餘每一頁照舊

第 4、6 條第一次跑就是綠的：它們守的是驗收條件，不需要新程式。第 4 條擋的是票面「注意」點名的那個錯——把橫幅掛到 `highlightedSymbol` 上，
選一個熱區之後橫幅就不見了。第 5 條的高度拿「同一張圖、沒帶符號進來」的同一個操作來比，不寫死 px。

### 小決定

- **關閉鍵是字「知道了」，不是 ×。**站在接待中心單手拿手機的人，一個 × 要猜。
- **橫幅不是 live region。**狀態列已經是 `role="status"`、既有測試大量用 `getByRole("status")` 找它；而橫幅在說明卡升起時讓位、收起時回來，
  做成 live region 的話每收一次卡片就重唸一次。它在 DOM 裡排在圖之前，照順序讀的人會先讀到它。代價見下面第 2 條。

### 留給規格的主人決定

1. **橫幅那句說明是為樑寫的，而出現的條件是「0 處」。**「建案平面圖多半不畫○○，它在施工圖與結構圖上」對樑成立，對下一個 0 處的符號不見得。
   今天只有樑（PRD §4.2），擺了兩道提醒：驗證器那條 warning 的訊息，以及「建置產物」那條測試的前提——圖上 0 處的符號不再只有樑時，
   它帶著指向 `absentSymbolBanner` 的訊息失敗。第二個出現的那一天，「為什麼圖上沒有」要不要搬進 symbol 資料，不在這張票。
2. **讀螢幕的人落地時不會被主動告知有這條橫幅。**D2 為高亮做了狀態列那一句；0 處時狀態列不說、「由橫幅接手」，但橫幅不會被唸出來，
   要照順序讀到它才知道。要不要讓狀態列在 0 處時說一句短的（例如「這張三房兩廳上看不到樑。」），是狀態列那一格怎麼分的事。
3. **矮螢幕沒有量。**驗收條件寫的是 375px，測試跑在 375 × 812。全圖時橫幅拿走的是留白；矮到留白不夠的螢幕上框會變矮，
   走的是既有的 RESIZE 高度那條路（stage 不動，ADR-0003），但沒有測試釘住「橫幅在時，矮螢幕上第二下仍然選得中」。

**沒改的：**

- **`oklch(0.68 0.15 75)` 在高亮與橫幅各寫一次。**兩條規則沒有共同的祖先 class 可以掛自訂屬性（橫幅在框外面）；拉到 `:root` 就變成
