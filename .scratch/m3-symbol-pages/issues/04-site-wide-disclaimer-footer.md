## 注意

**說明卡裡那一份要保留。** 卡片升起來時會蓋住頁尾，兩份服務的是不同時刻的同一個人——這不是重複。

**這張票會改變平面圖頁的可視高度，而檢視器的數學吃這個數字。** 視野的 fit 與上下限是**相對當前的框**算的（ADR-0004），框的高度來自一次 ResizeObserver 觀測（ADR-0003：說明卡是版面裡的一列）。頁尾一加，框就變矮。必須確認既有行為沒有被推歪——這是這張票唯一真正的風險，驗收條件裡那條「既有測試全綠」不是形式。

### 「卡片升起來時會蓋住頁尾」不成立

說明卡不是浮層，是版面裡的一列（ADR-0003）；頁尾照這張票要的做法，成了它下面的另一列。
兩列並存，**同一句免責一前一後印兩次**——實作時在 375×812 的瀏覽器裡直接看到。
票面說的「兩份服務的是不同時刻的同一個人」是對的，錯的只是「蓋住」這個機制。

三條路，2026-09-13 由使用者裁定第 1 條：

| | 做法 | 取捨 |
|---|---|---|
| **1（採用）** | 卡片升起時頁尾讓位：`body:has(#info-sheet) .footer { display: none }` | 任何一刻畫面上剛好一份，§6.4 一秒都沒失效；檢視器的框高回到加頁尾之前的數字（下表） |
| 2 | 兩份並存 | 誠實、不新增機制，但同一句話印兩次，看起來像壞掉；展開時圖只剩 17.5px |
| 3 | 平面圖頁維持 `100dvh`，頁尾落在第一屏外 | 檢視器完全不受影響，但那一頁變成捲得動的頁——票 03 決議 3 排除掉的東西 |

**機制是一條 CSS，不是從檢視器傳到根版面的 state。**根版面不必知道檢視器存在，說明卡也不必知道頁尾存在。
掛鉤是 `#info-sheet`——說明卡對外的名字（既有五份測試都用它找卡片），而 `<InfoSheet>` 只在確認符號後才掛上 DOM、
收起就卸掉，所以它「剛好在卡片升起時存在」。不掛在 CSS Module 雜湊出來的 class 上。理由寫在 `components/SiteFooter.module.css`。

### 檢視器的數學

`#floorplan-viewport` 的高度，375×812：

| 狀態 | 加頁尾之前 | 並存（未採用） | 讓位（採用） |
|---|---|---|---|
| 全圖／第一段候選 | 359.9 | 359.9 | 359.9 |
| 說明卡升起 | 334.7 | 277.3 | **334.7** |
| 說明卡展開 | 74.8 | **17.5** | **74.8** |

- 全圖那一列不動：圖高是長寬比給的，那一頁本來就有用不掉的留白，頁尾吃掉的是留白
- 並存的 17.5px：卡片上限寫成 `46dvh`／`78dvh`，相對的是螢幕，住進比螢幕矮的框就拿走更大的比例——
  ADR-0003 為 78dvh 寫的「平面圖僅餘 84px：足夠維持位置感」會被悄悄推翻。讓位之後它們回到原本的意思，所以沒有動
- **在瀏覽器裡走過，不只看測試數**（真滑鼠、真鍵盤，量數字、看截圖）：自己放大到 2× → 開卡 → 關卡，視野回原位 dx/dy/dw = 0；
  兩次框變動之後拖曳照樣平移 80px；「回到全圖」回到 fit；Enter 開卡焦點進卡、Esc 焦點回熱區；Tab 走 45 站沒有一站落在頁尾；
  第一次進站的引導與頁尾同時在畫面上、不互相壓住；每一步畫面上的免責都剛好一份

**一個門檻移動了，記下來，沒有修：**矮螢幕上，第二段的「重選」列與兩行狀態文字一出現，留白就用完，頁尾讓框變矮。
375×568 量到第一段候選時框從 359.9 變成 346.8px（−13.1）；加頁尾之前這台螢幕不會縮。
走的是既有的 `RESIZE` 高度那條路（stage 不動、按 fit 等比調整，ADR-0003；`pendingFocus`，ADR-0004 的票 08 那段），
第二下照樣選中、目標位移 0。所以不是新路徑，是**第二段會觸發框變動的螢幕高度，從約 524px 移到約 581px**。
測試專案只有 375×812，這一段只在走查裡驗過，沒有進 spec。

### 測試（`tests/site-footer.spec.ts`，5 條）

- **不列舉路由**：掃 `out/` 底下每一個 `.html`，都要有 `DISCLAIMER`（從 `@/lib/ui/copy` import，不在測試裡重打一次）。
  票 05 的分類頁、票 07 的首頁一產生就自動被要求。`404.html` 刻意不排除——它也由根版面產出
- 符號頁捲到底看得到；平面圖頁的頁尾在畫面上，整頁不捲動
- 卡片升起／展開／收起，**兩個方向、各兩半**：沒升起時頁尾那份在；升起時頁尾不在**而且**卡片那份在；每一步畫面上剛好一份。
  只斷言「頁尾藏起來了」的話，兩份一起不見也會過——那是 §6.4 失效，比印兩份更糟
- 頁尾裡沒有可聚焦的東西（先確認頁尾在，免得數到 0 的恆綠）

**紅過才綠，兩次反向驗證：**
1. 先故意做最直覺的版本（`{children}` 後面接 `<footer>`，不改框）：「平面圖頁不捲動」與卡片那條立刻紅——
   頁尾 `viewport ratio 0`（整條在第一屏之外），頁面變成捲得動的。票面警告的風險是真的
2. 做完之後拿掉 `:has` 那條規則重建：只有卡片那條紅，訊息是「說明卡升起來了，頁尾卻沒有讓位」，其餘 4 條綠。規則還原後逐 byte 一致

### 刻意沒做／順帶記下

- **`.page` 是 `flex: 1 1 0`，不是票上建議的 `1 1 auto`**：body 是 `min-height` 不是 `height`，flex-basis 給 auto 時，
  卡片一升起內容就把 body 撐高，頁面又變成捲得動的。理由寫在 `app/layouts/[id]/page.module.css`
- 短頁面的頁尾靠 `.footer { margin-top: auto }` 沉到底，不要求每一頁自己 flex-grow——分類頁與首頁不必知道頁尾存在
- **404 頁**：Next 內建的 404 有一塊 `height: 100vh`，頁尾落在它下面、要捲一下才看得到；那頁的內建樣式把 body 設成 `#fff`，
  頁尾的 `--paper` 底色會是一條略帶米色的帶子。沒有自訂的 `not-found.tsx`，不在這張票
- 票面的勾選框與 `Status:` 沒有動（這次只被允許附加 Comments）
