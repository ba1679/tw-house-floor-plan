## 為什麼這張是 M3 最重要的一張

這個按鈕是把 SEO 流量帶進產品核心體驗的**唯一入口**，PRD §6.2.1 說它的重要性高於首頁設計，§5 的轉換率指標就是在驗證它。

## 注意

**高亮是疊在 `browsing` 上的一層標記，不是第四個階段。** 高亮期間使用者本來就該能自由 pan/zoom、也該能直接開始新的第一段點擊——那正是 `browsing` 的行為。

**不得把這些熱區塞進候選集。** 理由**不是**命中判定會出錯（點擊是看階段分流的，`browsing` 之下第二段永遠不會接管，下一次點擊會用容錯半徑重算候選並覆蓋掉）。真正會壞的是**畫面與語意**：熱區的視覺狀態只看「在不在候選集裡」、不看階段，所以塞進去會被畫成與真正的第一段候選完全無法分辨的樣子——而使用者其實沒有點過任何東西。`CONTEXT.md` 已經把 `highlighted` 與 `candidate` / `selected` 分開登錄並明講不可互相概括。

**視野維持 fit，不自動放大。** 9 扇窗散在全圖，放大只會藏起其中幾處。

**目標格局取自符號的 `related_layouts`，不得寫死。** `related_layouts` 的意思是「這個符號的頁面該把讀者帶去哪張圖」，是編輯決定不是統計（`CONTEXT.md`）。

**靜態輸出下讀 query 參數要包 Suspense 邊界**，否則建置直接失敗。這是選 query 而非 hash 唯一的實作成本，先知道就不會撞牆。

### 做了什麼

- **狀態機**：`ViewerState.highlightedSymbol` 加一個 `HIGHLIGHT_SYMBOL` action，`Stage` 仍是三個。清掉高亮的地方只有兩處：
  `tap()`（手指的每一下）與 `confirmSelection()`（鍵盤 Enter 不經過 `tap()`）。其餘 action 一律留著——
  **`RESIZE` 也留**：落地後量到真正框寬的那一次就是「寬度變了」，它若跟候選一起清，落地就什麼都不亮。
- **ADR**：為什麼不是第四個 stage、為什麼不塞 `candidates`（寫的是**畫面與語意**那個理由，不是命中判定）、
  為什麼存 symbol id 不存熱區清單，寫進 `docs/adr/0006`——spec「Further Notes」要的那一份。CONTEXT.md 的 State／Stage 兩條各補一句。
- **讀網址**：`components/HighlightFromQuery.tsx`，一個什麼都不畫的 client 元件，**自己**待在 Suspense 邊界裡。
  邊界包在整個檢視器外面 build 也會過、瀏覽器裡也會亮，但圖會從靜態 HTML 裡消失——有一條測試讀 `out/` 釘住它。
  沒有照 `?fitLocked=1` 在 effect 裡讀 `window.location`：按鈕是 `<Link>` 的 client 端換頁，網址由 router 交出來比較穩。
- **參數名與網址形狀只寫一次**（`lib/viewer/highlight.ts`）：符號頁寫、檢視器讀。
- **畫法**：螢光筆的黃底、琥珀色邊，與候選的藍、選中的紅都不同色相。375px 全圖下截圖看過：9 扇窗一眼看得到，
  與其餘熱區那層淡藍提示分得開。
- **符號頁的按鈕**：PRD 原句「這個符號在真實格局裡長怎樣 →」，底下一行小字印格局名。`related_layouts` 有幾張就幾顆。
  墨色底，與首頁那顆進平面圖的按鈕同一個理由。截圖看過：排在出處之後、頁尾之前，375px 不溢出。
- **驗證器**：`related_layouts` 對不到格局是 error，訊息說得出那是一顆通往 404 的按鈕。原本「宣稱出現在 X 但該圖沒有 hotspot」
  那條 warning 收窄到存在的格局，不為同一個壞 id 報兩次。「存在」以 floorplan 為準，因為網址由 floorplan 檔名決定。
- **測試工具**：`blankSpot` / `pinch` / `dragLeft` / `markingOf` / `painted` 收進 `tests/viewer-page.ts`；
  pan-zoom、keyboard、affordance-hint 三份原本各抄一份的改成 import。

### 小決定

- **按鈕底下印格局名。** 票面只給了那一句。多一行是為了第 2 張圖進來的那一天：兩顆都只有那一句的話，
  讀螢幕的人聽到兩個一模一樣的連結，分不出哪個通往哪張圖。今天只有一顆，看起來像多印了一行。
- **「階段維持 browsing」「視野維持 fit」用看得到的東西測**：沒有「重選」、沒有「回到全圖」、圖寬等於框寬。不讀 `data-stage`。
- **「分辨得出來」用 computed style 測**：高亮與候選、與平常熱區的 fill 和 stroke 都不同。它擋得住「沒寫樣式」與
  「照抄候選的樣式」，擋不住「兩個顏色很接近」——那一道靠截圖。
- **「目標格局取自 `related_layouts`」那條擋不住寫死**：14 筆全是同一張圖。與票 07 平面圖頁標題那條同一個限制，測試註解照實寫下。

### 留給規格的主人決定

1. **雙擊會清掉高亮。** spec 寫「任何 `TAP` 清掉高亮」，而雙擊的第一下在手勢層就是一次 TAP（第二下才認得出是雙擊）。
   結果是雙指縮放留得住高亮、雙擊留不住：習慣雙擊的人想湊近看某一扇窗，放大之後標記就沒了（user story 16）。
   現狀照字面做，有測試釘住、ADR-0006「後果」寫明。要改的話改的是 `tap()` 清掉的條件（例如沒圈出任何候選的那一下不清），
   不是把高亮升成 stage。
2. **高亮只有畫面，狀態列不說話。** 讀螢幕的人落地時聽不到「標出了 9 處窗」。狀態列那一格落地時屬於第一次進站的引導（票 05），
   而從 Google 經符號頁進來的人幾乎都是第一次來——讓給高亮，他就再也聽不到那句引導（引導在出現那一刻就記成看過）。
   兩者怎麼分那一格，沒有在這張票裡定。
3. **`related_layouts` 為空陣列的符號，符號頁安靜地沒有按鈕。** 驗證器沒擋（spec 的必填內容欄位清單沒有它）。
   那是把搜尋流量帶進平面圖的唯一入口，要不要列為必填。
4. **`?symbol=` 帶一個不存在的 id**（手打或剪壞的網址）：狀態機照收，圖上 0 處亮——與樑是同一個狀態。
   票 09 的橫幅若以「對到 0 處」為條件，會對打錯的網址也跳出樑的說明。這一條票 09 動手時要先決定。
