# 07: 首頁

**What to build:** 打開網站根網址的人看到一句話就知道這裡在幹嘛，然後有一個明顯的按鈕直接進三房兩廳平面圖；想查特定符號的話這裡也有搜尋框，想瀏覽的話有三個分類入口。

**Blocked by:** 05（分類入口要連得到分類頁）、06（搜尋框）

**Status:** done

規格：`.scratch/m3-symbol-pages/spec.md` 的「路由」「全站」。PRD §8 把「首頁 → 平面圖」列為兩條入站路徑之一。

## 現況

**根網址目前是 404。** 不是佔位頁、不是轉址——打開就是錯誤。

**平面圖頁也沒有自己的標題。** `/layouts/3b2l_standard` 用的是根版面那一句「平面圖教學」——首頁一做出來，兩頁在搜尋結果上就是同一個名字。spec 的「全站」寫著「M3 一併修掉」，但原本沒有任何一張票認領它。

## 注意

**要小。** 一句主張、一個進平面圖的按鈕、搜尋框、三個分類入口。**不做**長篇產品敘事、示意圖、統計數字、動畫。一頁捲得完。

它不是這個產品的主要入口（§6.2.1 明講大多數人從 Google 直接落在符號頁），但它是唯一一條「產品敘事」路徑，而且根網址回 404 的網站拿不出手。

**平面圖頁的標題在這張票一起定。** 原本那條「與平面圖頁的標題不同」只約束首頁：平面圖頁繼續用根版面的「平面圖教學」、首頁隨便取一個別的名字，那條照樣會過，而 spec 要修的那件事一個字都沒動。兩頁的標題是對照著取的，放在同一張票裡定，才不會各取各的。

標題與描述由該 layout 的資料生成（例如 `floorplan.name`），**不寫死 `3b2l_standard`**——spec「路由」的規矩，M6 加第 2 張圖時不必回頭改。字放在 `lib/ui/copy.ts`，與 `symbolPageTitle`、`categoryPageTitle` 同一個作法。

**小心 `<h1>`。** 平面圖頁的 `<h1>` 是 100dvh 版面裡的一列（ADR-0003）。它在 375px 換成兩行的話，說明卡升起時與矮螢幕上，檢視器的框就跟著變矮——與票 04 的頁尾同一類風險。只改 `<title>` 與 meta 就碰不到它；真要讓 `<h1>` 跟著變，就得重走票 04 驗過的那一套。

### 兩頁的標題，對照著取

| | `<title>` | `<h1>` |
|---|---|---|
| 首頁 | 平面圖教學：看懂建案平面圖上的符號 | 一張平面圖，你真的看得懂嗎？ |
| 平面圖頁 | 三房兩廳平面圖怎麼看？ | 三房兩廳（沒動） |

- 首頁說的是網站，站名在前；平面圖頁說的是那一張圖，長得像有人會打進 Google 的那句話。
  兩者都是 `lib/ui/copy.ts` 的常數／函式（`HOME_PAGE_TITLE`、`layoutPageTitle(name)`），平面圖頁那一句
  由 `floorplan.name` 生成。
- **兩頁的 `<title>` 都與 `<h1>` 不同句**，與符號頁、分類頁「兩者同一句」的規矩刻意不同，理由各寫在程式裡：
  平面圖頁是票面「小心 `<h1>`」那一條（只改 `<title>` 與 meta）；首頁的主張是一個問句，放進搜尋結果裡看不出是哪個網站。
- 根版面的標題改成 `SITE_NAME` 常數，字沒變。它現在只剩 404 頁在用。
- 測試不從程式抄「根版面那一句」：**看 `out/404.html`**——它由根版面產出、沒有自己的標題。
  首頁那條另外掃過 `out/` 每一張有內容的頁，斷言沒有一頁與首頁同名或同描述（不列舉路由，同 site-footer 的理由）。

### 小決定

- **有幾張圖就有幾個按鈕**，由 `listLayoutIds()` 決定，今天是一個。不挑「第一張」當主打：哪一張該主打是編輯決定，
  不該藏在排序裡。M6 多一張圖時首頁會自己長出第二個按鈕——那時要不要改成只主打一張，是 M6 的事。
- **主張底下多一句說明**（`HOME_LEDE`）。PRD §8 的主張「一張平面圖，你真的看得懂嗎？」是一個問句，
  說不出「這裡在幹嘛」（票面 What to build 的第一個要求），所以緊接一句說明。只有一句，沒有展開。
- 按鈕底色用墨色不用 `--accent`：`--accent` 是全站的連結色，白字壓在上面的對比不到 4.5:1。
- 分類入口每一列只有中文名與英文小字，**不附「共 N 個符號」**：那是分類頁自己的前言，搬到首頁就是票面不要的統計數字。
  英文小字 `aria-hidden`，否則讀螢幕的人聽到同一個名字兩次。
- 搜尋框直接放 `<SearchBox index={loadSearchIndex()} />`，與分類頁同一個元件、同一份索引。首頁的測試只問它在不在、
  打字是不是當場出結果（spec 第 13 條）；比對、注音、鍵盤、找不到的回饋 search-box.spec.ts 已經在分類頁測過，不重測。
- **抽出了 `app/reading.module.css`。** 分類頁的 CSS 註解原本說好「第三張讀物頁（票 07 的首頁）若也要同一套，那時就該抽出來，
  而不是抄第三份」。版心、標題上方小字、標題字型三頁共用，各頁 `composes` 進去；gap 與標題 margin 三頁不同，留在各頁。
  **同一個屬性不在共用檔與各頁同時寫**——composes 進來的 class 誰蓋過誰取決於打包順序。
  樣式沒有測試，所以在瀏覽器裡量過：符號頁（gap 24px、標題 margin-top −14px）與分類頁（gap 10px、margin 0）的
  版心、小字、標題 computed style 與抽出前 CSS 裡寫的值一致。

### 兩條測試一寫下去就是綠的

「375px 下不溢出」與「首頁內容區裡沒有任何一張圖」不是由紅轉綠驅動實作的，是驗收條件的護欄：頁面寫出來時就沒有溢出、沒有圖。
兩條都先確認站在首頁上再斷言（404 頁也不溢出、也沒有圖）。
票面「沒有長篇敘事、統計數字」量不出來，沒有寫成測試——搜尋框的標籤「搜尋全部 14 個符號」本身就帶數字，數字掃描會誤傷。
