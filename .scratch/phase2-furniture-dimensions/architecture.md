# 家具與尺寸判讀：架構與拆票依據

Status: ticketed architecture proposal

依已確認 spec 及 C「逐步讀圖」設計 brief。本文件描述本里程碑要落實的 Module／Interface／Seam，不是通用課程平台設計，也不代表程式已存在。

## 目前程式的限制

- FloorPlanRenderer 的公開 Interface 接受 FloorPlan、房間畫法與疊加內容；沒有教學局部呈現的設定。既有 View 與 Stage 服務互動檢視器，不能拿來持有導讀步驟。
- 尺寸標註由資料給定端點與文字，但目前水平線一律放在整圖上緣、垂直線放在左緣。房間內尺寸不是加一筆資料就自動排好。
- FloorPlan 的載入清單同時驅動公開 Layout 入口及靜態頁面。陌生局部教學範例不能為了重用載入器而被算成新的完整格局。
- 找找看的 Answer 比對題目 Symbol 與選中 Hotspot 的 Symbol，並連動 Familiarity。判讀作答確認的是文字選項，兩者語意不能互換。
- 產生器內建家具尺寸與留空距離是生成示意的條件，不是已查證的通用住宅舒適度或法規門檻。

以上已透過 codegraph 與 ADR-0003、0005、0007 核對。本批不需要先做全站 prefactor；真正需要的最小擴充隨第一個使用它的垂直交付一起落地。

## Module 與 Interface

### 1. 導讀內容 Module

持有導讀步驟、教學圖參照、明示條件、主張依據、判讀題與理由、提問清單的單一內容來源。Interface 依消費者提供閱讀、練習及清單所需的投影，不把查證工作備註整批序列化給瀏覽器。

內容投影必須區分「讀者已看得到的條件」與「只是內部幾何」。題目的判定及等價文字只能使用前者。來源定位及示範假設是可核對的內容，不借用既有 Symbol Source Tier 或 caution 冒充新主張已查證。

### 2. 教學圖 Module

Interface 接受一份已解析的教學圖描述：原圖參照、觀察範圍、明示標註／條件及等價文字。裁切、留白、文字可讀性、標註與原始幾何的對應集中在它的 Implementation；呼叫者不各自計算房間邊界或另畫床與門。

沿用 FloorPlan 與 Artwork 的同一套幾何及畫法，只對共享 Renderer 做本批需要的最小擴充。既有互動檢視器仍使用完整圖面與原本 View；靜態教學圖的觀察範圍不改變 ViewerState、命中判定、Stage 或 InfoSheet。

尺寸教學先使用本批真正需要的標註，不建立通用尺寸排版引擎。若選定範例需要新增內尺寸，端點、單位、文字及留白必須由同一份明列條件產生並驗證；不能複製一段硬寫尺寸線到每個頁面。

陌生範例沿用生成流程，維護原始描述與產物；不手改 FloorPlan，不使用 AI 圖稿當教材。教學範例與公開完整 Layout 的清單隔離，不為局部練習新增一戶可自由探索的完整格局，也不複製一套家具求解或門扇弧算法。

### 3. 逐步導讀 Module

Interface 接受已投影的導讀內容與一般導覽目的地。它持有當步位置、前後切換、標題焦點及來源展開，並呼叫教學圖 Module；不持有 Symbol 熟悉度、個人家具設定或檢視器 Stage。

手機上下讀、桌面圖文相鄰；內容增加時自然捲動。完整格局、練習及清單都是一般導覽，不以覆蓋圖面的 modal 連接。不另存續讀或完成紀錄。

### 4. 判讀練習 Module

Interface 接受同一張陌生教學圖、三道判讀題、明列條件及回饋理由。它自己持有「未確認選項／已確認判斷／顯示理由／下一題／結束／重試」，不把假的 Symbol 或 Hotspot 塞進 Round。

正誤及理由不下放給圖面；Familiarity 不被讀寫。作答前不提前渲染正解或理由到可見及無障礙內容。靜態網站的回饋資料可能存在於瀏覽器，這不是保密考試系統，不能承諾答案無法由開發工具取得。

### 5. 提問清單 Module

Interface 接受同一份內容來源投影出的問題與理由。螢幕與列印共用內容；瀏覽器列印 media 是呈現 Adapter，不另設文件生成後端。直接入口與完成導讀／練習無關。

## 測試 Seam 與查證

主要 Seam 是實際頁面：從可用入口讀到正確圖面與說明、切換、確認答案及看理由、回看／重試、直接開啟及列印清單。每張交付票自己包含所需來源查證、建置驗證與真瀏覽器測試，不把測試堆到最後才做。

資料驗證沿用建置流程，逐批擴充圖面參照、步驟／選項／答案參照、理由、出處或範例推導依據的檢查。刻意未知的資料不補零；新增尺寸要能核對原始條件。建置通過不取代語意核對、答案唯一性及實際原文閱讀。

每次動到共享圖面都檢查受影響的既有全圖、找找看、兩段式點擊、尺寸及縮放；每個新閱讀／作答交付都驗手機、鍵盤與等價資訊。最後整合檢查只補全旅程與發布建置，不代替前面票的測試。

實際內容查證在各票內依 repo 的 research 流程派背景工作、與程式線並行。這一輪只做規劃，沒有宣告教材來源已核對。

## 領域與決策文件

已把 spec／brief 中明確的導讀、導讀步驟、教學圖、判讀練習、判讀作答與提問清單記入 CONTEXT，避免與既有找找看語意混用。

本批延伸既有靜態建置、生成 FloorPlan 與 React Artwork 的做法，不推翻現有 ADR，也沒有需要先記為不可逆的新決定。實作若發現必須偏離，再提出真正的取捨與受影響範圍，不預先寫推測型 ADR。

## 驗收的兩個終點

程式與內容檢查完成後只能稱為「可試用」。五位目標情境讀者中至少四位在另一張未見圖上，獨立指出有依據的觀察、未知資訊與有效追問，且反覆誤解已修正重測，才滿足 spec 的里程碑驗收；不以原題重試答對代替。
