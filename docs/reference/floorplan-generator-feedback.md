# 給 `floorplan-generator` skill 的回饋

**來源**：《室內設計裝修製圖規範》（中華民國室內設計裝修商業同業公會全國聯合會，70 頁）。
逐項出處見 [`docs/reference/naid-symbols.md`](naid-symbols.md)。本文頁碼皆為該 PDF 頁碼。

---

## 先講結論

1. **這個 skill 的架構沒有問題，不要重做。** 「JSON 是 source of truth、座標由程式推導、傢俱只給意圖」這幾條與製圖規範完全相容——規範管的是「畫出來長什麼樣」，不管「誰算座標」。以下全部是**畫法層（renderer + schema enum）**的建議，動不到管線設計。
2. **最該補的一件事：窗的三種 `type` 目前畫起來一模一樣。** 對一個「教人辨認符號」的網站，這是核心資產畫錯。
3. **最該先知道的一件事**：規範第 9 節（p9 表 3）把平面配置圖、天花板圖、開關插座位置圖、給排水配置圖列為**四張不同的圖**。PRD 想把 20 個符號放進同一張三房兩廳圖，在實務上不存在這種圖。這不是要放棄，是要**明講它是教學合成圖**——見 §C1。

---

## A. 立刻可做，成本低，標準有明文

### A1. 窗要分型畫 —— 目前 fixed / casement / sliding 完全相同

`scripts/render_svg.py` 的 `# --- 窗 ---` 區塊，不論 `wn["type"]` 是什麼，一律畫三條平行線。
但 `schema` 已經有 `window.type: [fixed, casement, sliding]` 這個資訊，只是沒被用到。

規範 p24 表 9 給了可區分的畫法（完整 18 種見對照表 §5）：

| type | 畫法 |
|---|---|
| `fixed` 固定窗 | 窗框帶內 **2 條平行細實線**，兩端窗樘記號 |
| `sliding` 橫拉窗 | 框帶內兩段線**於中央錯開**、交會處一個小接點（雙橫拉） |
| `casement` 平開窗 | 窗扇線 ＋ **90° 開啟弧，向室外側** |

順帶三件事：

- 表 9 的第一項叫**「牆開窗」**，畫法是開口只有一條線——那才是「純開口、沒有窗」。本專案若有「開放式陽台的開口」需求，這是標準名稱。
- **紗窗**是在窗線旁再加一條細虛線。台灣住宅幾乎都有紗窗，這是很好的教學細節。
- 表 9 標了三種橫拉窗的**最大開口比例**：三橫觀景拉窗 1/3、三橫拉窗 2/3、四橫拉窗 1/2。這是「這扇窗實際能開多大」的資訊，對買房者有用，可以進 symbol 的 `caution`。

### A2. 線寬建立階層 —— 目前是 magic number

現在 renderer 裡散落 `stroke-width="4"`、`"3"`、`"7"`、`"2"`。
規範 p47 表 24 給了完整的筆粗階層（以 S:1/50 為基準），而本專案的 SVG 座標＝世界座標 cm、圖面比例 1/50，
換算公式乾淨：**`stroke-width(cm) = 筆粗(mm) × 5`**。

```python
# 依《室內設計裝修製圖規範》p47 表 24，S:1/50。stroke-width(cm) = 筆粗(mm) × 5
LW = {
    "structure_cut": 3.0,   # 0.6mm 特粗：RC/磚造主要結構剖、輪廓線—牆、梁、柱
    "structure_elev": 2.0,  # 0.4mm 粗實：主要結構立面線
    "major": 1.5,           # 0.3mm 中粗：主要裝修建材、主要家具外圍線、輕隔間
    "frame": 1.0,           # 0.2mm 中實：高程線、窗台線、門框、窗框
    "minor": 0.5,           # 0.1mm 細實：家具次要副線、尺寸標註線
    "hair": 0.25,           # 0.05mm 微細：材質剖面線、面材紋理線
}
```

同一張表也給了顏色（紅 / 黃 / 綠 / 青 / 藍 / 紫 / 白）與手繪鉛筆硬度（2B/B/HB/F/H）。
現在的 `PALETTE` 是自訂配色，這沒問題（列印用的筆色與螢幕顯示是兩回事），但**線粗的相對關係應該照表 24**——
目前家具線（3）比門線（4）細、窗線（3~4）與門線幾乎同粗，而標準要求「結構 > 家具外圍 > 門窗框 > 家具副線」是四個明確的階。

### A3. 牆與柱要用**填色深淺**區分，不是形狀

表 24 最後兩列：

| 筆號 | 顏色 | 應用 |
|---|---|---|
| 8 | **深灰** | **柱**填實 |
| 9 | **淺灰** | **牆**填實 |

目前 renderer 的牆一律 `#2b2b2b`（接近全黑），而且**沒有柱的概念**。
PRD 的 20 個符號裡「柱」是其中一個，而規範說柱與牆的差別就在填色深淺——這條規則便宜且可直接實作。

### A4. 家具的「高度」是有畫法語意的，正好對上 `rules/furniture.md` 的分類

規範 p25 表 10 備考：

| 畫法 | 意思 | 出處 |
|---|---|---|
| 矩形內畫 **X** | **高櫃** | 「以 120~150cm 平切下視為原則」 |
| 矩形內畫**一條斜線** | **半高櫃** | 「120~150cm 半高櫃加斜線表示」 |
| 矩形**不加記號** | 矮櫃 | （在切面以下） |
| **虛線**矩形 | 吊櫃 | 「書桌吊櫃以虛線表示」 |

`rules/furniture.md` 已經有 `TALL` / `WALL_MOUNTED` / `FREESTANDING` 三類，但那是**碰撞規則**用的；
規範說這三類在**畫法上本來就該長得不一樣**。等於現成的分類可以直接驅動渲染：

- `wardrobe` / `refrigerator`（`TALL`）→ 加 X
- `tv`（`WALL_MOUNTED`，掛在牆上、在切面以上）→ 虛線
- `kitchen_counter`（下櫃）→ 不加記號

這件事的價值不只是好看：它是教學網站可以直接拿去用的一課——**實線＝切到的或看到的，虛線＝頭頂上的**（見 A5）。

### A5. 把「平面圖 = 離地 120~150cm 平切下視」寫進 `rules/geometry.md`

規範 p44 §15.2：

> 「平面圖為約在地面上 120~150cm 平切下視，作正投影，所得之剖面圖……此一剖面不論其距地板高度為若干，**均須切過該層所有門窗開口**。」

`rules/geometry.md` 現在解釋了「為什麼你不能直接寫座標」，但沒解釋「為什麼平面圖長這樣」。
這一句是**高櫃畫 X、吊櫃畫虛線、樑畫長虛線**三條規則的共同理由，值得寫成一段，因為它同時是：

- renderer 的畫法依據
- 教學網站最有價值的一段內容
- 未來要不要支援天花板圖時的分界線

## B. 需要動 schema

### B1. 門的 `type` enum 只有三種，規範有 14 種

`schema` 現在是 `["single", "double", "sliding"]`。表 8（p23）的完整清單見對照表 §3。
以台灣住宅實務，建議至少補這四種：

| 建議值 | 名稱 | 為什麼台灣需要 |
|---|---|---|
| `unequal_pair` | **子母門** | 台灣公寓大門最常見的形式（一大一小），現在只能勉強畫成 `double` |
| `folding` | 折疊門 | 浴室、更衣室、陽台常見 |
| `pocket` | 拉進門（口袋門） | 小坪數衛浴的標準解，與 `sliding` 的畫法**不同**（門扇收進牆體） |
| `opening` | **出入口（無門扇）** | 見下 |

`opening` 特別值得補。`rules/geometry.md` 在講「開放式廚房」時寫：

> 「刪門會讓廚房從大門走不到，validator 的連通檢查會擋下來，所以請改成**寬開口而不是無開口**。」

這個「寬開口」在規範裡有正式名稱與畫法：**表 8 第一項「出入口」——牆斷開、不畫門扇、開口中央一個小三角記號**。
目前用「加寬的 sliding」代替，畫出來會多兩片不存在的門扇。補 `opening` 型別可以讓這個 workaround 變成正解。

另外，**門的開啟弧線畫實線或虛線是有語意的**，不是美術選擇。p23 備考：

> 「門扇之軌跡線如以**實線**表示，則**可遮蔽**地板材質線；如以**虛線**表示，則**不可遮蔽**之。」

目前 renderer 畫虛線弧（`stroke-dasharray="14 10"`），依規範就代表「不遮蔽地板材質線」——
這與現在的畫法一致，沒有 bug，但值得在程式碼註解裡寫明**為什麼是虛線**，免得日後有人「順手改成實線」而不知道自己改掉了一個語意。
另一個小差異：表 8 的門扇畫成**有厚度的細長方形**，不是一條線。

### B2. 沒有「樑」這個東西，但 PRD 要它

PRD 的 20 個符號裡有「樑」與「暗樑」，`floorplan.schema.json` 裡沒有任何對應。
規範 p18 表 6 有明文：

> **長虛線**：表示平面圖上部之主結構投影線，如：**梁線**。

而且 p46 表 23 的 CAD 圖層表裡，「09 梁位 `BE` 紫 **Hidden 2**」是一個**獨立圖層**、獨立線型。

建議在 `layout`（格局）加一個選填的 `beams` 陣列（矩形，可相對房間下座標，就像現在的 `hotspots`），
renderer 畫成長虛線矩形、獨立 `<g id="beams" data-layer="BE">`。
理由：這是台灣買房者最在意的東西之一（壓樑、壓床、樑下高度），而且它是**唯一必須用「頭頂上的虛線」表達的元素**，
沒有它，「實線＝切到的、虛線＝頭頂上的」這一課就講不完整。

> ⚠ 一個誠實的限制：本規範**只說「梁線」，沒有區分「明樑／暗樑」**。
> 「暗樑」是台灣房產與室內設計圈的用語，不是製圖標準用語。這件事應該回寫進 `data/symbols.json` 的備註，
> 也建議 PRD 重新檢視「暗樑」是不是該與「樑」合併成一個符號。

### B3. 尺寸標註規範要求**三層**，目前只有一層

p19 §12(d)：

> 「平面圖之尺寸標示，應有**固定家具尺寸、單元空間尺寸及總尺寸**三層標示。」

現在 `render_svg.py` 的 `annotations` 只畫了外框總尺寸（W / H 各一條）。
補「單元空間尺寸」（每個房間沿外緣的一條尺寸鏈）是中等成本、高回報：
它讓生成的圖從「示意圖」變成「看起來像真的施工圖」，而 §12 的其他規定也值得順手照做：

- 尺度線用**細實線**，端點符號為 **箭號 Arrow／點號 Dot／短斜線 Tick** 三選一，**不得混用**（目前畫的是與尺度線垂直的短線，嚴格說三者皆非；挑一種、全圖一致即可）
- 尺度數字註於尺度線**上方**
- 指標線與水平線成 **45° 或 60°**，避免與尺度線平行

### B4. 圖層代號應該對齊表 23

p46 表 23 是台灣室內設計 CAD 的通用圖層命名。renderer 的 `<g>` 已經分好組了，只差掛上代號：

| 現有 `<g id>` | 建議加 | 圖層 |
|---|---|---|
| `walls` | `data-layer="WL"` | 02 牆 |
| `windows` | `data-layer="WI"` | 03 窗戶 |
| `doors` | `data-layer="DR"` | 04 門 |
| `furniture` | `data-layer="FUM"` / `"FUF"` | 07 活動家具 / 08 **固定家具** |
| `annotations` | `data-layer="SI"` | 10 尺寸 |
| `room-labels` | `data-layer="TE"` | 11 文字 |
| （新增 beams） | `data-layer="BE"` | 09 梁位 |

**活動家具與固定家具在標準裡是兩個圖層**，這對買房教學特別有意義——
「附不附」看的就是這條線。`rules/furniture.md` 的型錄可以順手加一個 `fixed: true/false` 欄位
（`kitchen_counter`、`wardrobe`（系統櫃）、`toilet`、`sink`、`bathtub` 屬固定；`sofa`、`bed`、`dining_table` 屬活動）。

## C. 需要你決策的

### C1. 「20 個符號放進同一張平面圖」與製圖實務衝突 —— 這是 PRD §12 那條風險的答案

規範 p9 表 3 列出室內設計圖說的編排順序，其中這幾張是**分開的圖**：

| 項次 | 圖名 |
|---|---|
| 7 | 平面配置圖 |
| 9 | 造型天花板配置圖 |
| 11 | 天花照明配置圖 |
| 13 | 空調配置圖 |
| 21 | 開關插座位置圖 |
| 26 | 消防設備圖 |
| 30 | 給排水配置圖 |

而且 p44 §15.3(a) 明說：**「天花板圖中不須繪置平面圖中門窗的符號」**——連門窗都不畫在天花板圖上。

也就是說：**撒水頭、偵煙器、燈具、開關插座、空調，在真實圖說裡不會和家具擺設出現在同一張平面圖上。**
PRD §12 把「20 個符號能否自然地全部出現在同一張三房兩廳圖」列為未驗證風險——
這份規範等於回答了：**不能，實務上沒有這種圖。**

三個選項，我的建議是第 3 個：

1. 砍掉設備類符號，只留結構／門窗／家具家配 → 但撒水頭是目前**唯一 verified 且注意事項寫得最好**的符號，砍掉可惜
2. 硬塞進一張圖 → 圖會不像真的，違反 PRD「教人正確辨認」的初衷
3. **一份 layout、兩個圖層**：同一份 `floorplan.json` 產出「平面配置圖」與「天花／設備圖」兩個 SVG 圖層，
   viewer 用一個切換鈕（或 hotspot 分組）呈現。資料仍是一份，符號仍是 20 個，但**符號出現在它該出現的那張圖上**——
   而「為什麼撒水頭不畫在平面配置圖上」本身就是一堂課。

這件事影響 PRD 而不只是 skill，所以列在這裡讓你決定，skill 不必自行處理。

### C2. `symbol_map.json` 可以開始填了，但要小心 tier

`SKILL.md` 硬規則 5「不要臆測符號對應……查不到就是 `null`」**完全正確，請保留**。
差別是現在「查得到」了——但**查到的東西 tier 不一樣**：

| 表 | 內容 | 標題有無 CNS 引用 | 可得 tier |
|---|---|---|---|
| 表 14 / 17 / 18 / 20 / 21 | 給排水衛生、電氣插座、空調、消防、電信 | **有**「引用 CNS11567，A1042 建築製圖」 | `cns`（轉載） |
| **表 8 / 表 9** | **門、樓梯、升降機 / 窗** | **無** | `convention` |

也就是說：**`door_single_swing` 憑這份文件只能標 `convention`，不能標 `cns`**。
CNS 11567（NT$165）該買的結論不變，這份文件的作用是「先解除阻塞、可以先開工」。

建議的 `rules/symbol_map.json`（**等 `data/symbols.json` 正式登錄這些 id 之後再填入**，
在那之前維持 `null` 是對的）：

```jsonc
{
  "_note": "門窗類型 → data/symbols.*.json 的 symbol.id。畫法依據見 docs/reference/naid-symbols.md；門窗（表 8/9）為公會規範 convention 級，非 CNS 原文。",
  "door.single":   "door_single_swing",     // p23 表 8 單開門
  "door.double":   "door_double_swing",     // p23 表 8 雙開門
  "door.sliding":  "door_sliding_single",   // p23 表 8 單拉門
  "door.opening":  "entrance_opening",      // p23 表 8 出入口（若採納 B1）
  "window.fixed":    "window_fixed",        // p24 表 9 固定窗
  "window.casement": "window_casement_single", // p24 表 9 單開窗
  "window.sliding":  "window_sliding_2"     // p24 表 9 雙橫拉窗
}
```

## D. 建議**不要**做的

| 不要做 | 為什麼 |
|---|---|
| 把燈具、空調、電信符號放進 `expand_layout.py` | 它們屬於天花板圖與設備圖（見 C1）。撒水頭、偵煙器維持現在的做法——用 spec 的 `hotspots` 手動標，是對的 |
| 為了合規改成 mm | 規範 p7 §4 要求以 mm 為單位且不寫單位符號，但本專案內部用 cm 是刻意的（`rules/geometry.md` 有說明）。**只要輸出時一律把單位寫出來**就不會誤讀。圖名依 p14 應寫成 `一樓平面配置圖 S:1/50 mm` |
| 導入植栽、車輛、事務機器圖例（表 11、13） | 住宅室內平面用不到 |
| 支援非矩形房間以符合「實形」 | 表 10、11、12 的備考都寫「可畫**輪廓或實形**自訂」——標準本身就允許用輪廓表示。切割樹的矩形限制不違規 |

## E. 其他小補充（成本極低）

| 項目 | 出處 | 做法 |
|---|---|---|
| **指北針** | p16 §10(a)「平面配置圖……應標示指北針」 | 圖角加一個 `N` 圓形箭頭。規範同時規定「以圖之上方為北方」，與 skill 的座標系一致 |
| **出入口方位** | p16 §10(b)「作圖時出入口應置於圖面**下方或右方**為原則」 | 這是 `validate_floorplan.py` 可以直接加的一條 warning：`role: "entrance"` 的門不在 `s` 或 `e` 側就提醒 |

| **房間標籤加代號** | p48 表 25 | `客廳 L`、`主臥 M.B.R`、`廚房 K`、`陽台 BAL`、`廁所 W.C`。真實建案平面圖上就是這樣寫，認得代號本身就是教學目標。缺對應的只有 `hallway` 與 `study` |
